Bài 17 - SSE & FPU

Status doneTags step, x87, sse, avx, cr0, cr4, xcr0, fxsave, xsave, context switch

Hàm: initiateSSE() (cpu/system.c), đoạn "Save & load appropriate FPU state" trong schedule() (multitasking/schedule.c), khởi tạo fpuenv trong taskCreate() (multitasking/task.c) · Phụ thuộc: đổi task từ Bài 12 - Multitasking & Scheduler, task ring 3 từ Bài 16 - Fast Syscalls.

Mục đích

Cho chương trình dùng phép tính số thực và lệnh SIMD, và giữ đúng các thanh ghi đó khi đổi task.

Chương trình biên dịch cho x86-64 dùng SSE cho mọi phép tính float/double, và memcpy/strlen của libc thường dùng SSE hoặc AVX. Các lệnh đó gây #UD cho tới khi kernel bật chúng trong CR0, CR4 và XCR0. Bật xong lại thêm một trách nhiệm: thanh ghi FPU/SSE/AVX là một bộ duy nhất của CPU, nên mỗi lần đổi task kernel phải cất bộ của task cũ và nạp bộ của task mới. Bài này đọc cả hai phần trong cavOS.

Nói thật đơn giản

CPU có một bàn tính lớn (thanh ghi x87, XMM, YMM). Lúc mới bật máy, bàn tính bị khoá: ai đụng vào là báo lỗi. initiateSSE() mở khoá. Bàn tính chỉ có một cái, mà nhiều người (task) thay nhau dùng. Mỗi lần đổi người, phải chụp lại các con số đang nằm trên bàn của người cũ, và bày lại số của người mới. Nếu tấm ảnh chụp thiếu một góc (cavOS chụp bằng fxsave, không thấy nửa trên của YMM), thì người quay lại sẽ thấy góc đó mang số của người khác.

Cần biết trước

Ba lớp thanh ghi, bốn chỗ bật, hai lệnh lưu.

  • Ba lớp thanh ghi. x87: 8 thanh ghi 80 bit dạng stack (ST(0)–ST(7)) và từ điều khiển FCW. SSE: 16 thanh ghi XMM0–XMM15 128 bit và thanh ghi trạng thái MXCSR. AVX: mở rộng thành YMM0–YMM15 256 bit; nửa thấp của YMMn chính là XMMn.
  • Chỗ bật. CR0.EM = 0 (không giả lập FPU), CR0.MP = 1, CR0.NE = 1 (lỗi x87 báo bằng #MF thay vì chân IRQ cũ); CR4.OSFXSR (OS biết lưu bằng fxsave, cho phép lệnh SSE) và CR4.OSXMMEXCPT (OS xử lý #XM); CR4.OSXSAVE (cho phép xsave/xgetbv/xsetbv); XCR0 chọn thành phần nào được dùng: bit 0 x87, bit 1 SSE, bit 2 AVX.
  • Hai lệnh lưu. fxsave/fxrstor: vùng 512 byte căn 16, chứa x87, XMM0–15 và MXCSR. xsave/xrstor: vùng căn 64, cỡ do CPUID leaf 0xD báo, lưu mọi thành phần trong mặt nạ EDX:EAX AND XCR0, kể cả nửa cao YMM.
  • Đã gặp: schedule() cất khung thanh ghi đa dụng của task cũ và dựng khung của task mới ở Bài 12. Thanh ghi FPU nằm ngoài khung đó, nên cần một bước riêng.

SSE được bật ngay trước khi chạy chương trình user đầu tiên. Trước đó chỉ có kernel thread, mà kernel không bao giờ dùng FPU (mục 3).

2. initiateSSE()

c
void initiateSSE() {
  if (!checkSSE()) { ... panic(); }      // CPUID.1 EDX bit 25
  if (!checkFXSR()) { ... panic(); }     // CPUID.1 EDX bit 24

  // enable SSE
  asm volatile("mov %%cr0, %%rax;"
               "and $0xFFFB, %%ax;"          // CR0.EM = 0
               "or  $2, %%eax;"              // CR0.MP = 1
               "mov %%rax, %%cr0;"
               "mov %%cr4, %%rax;"
               "or  $0b11000000000, %%rax;"  // CR4.OSFXSR (bit 9) | CR4.OSXMMEXCPT (bit 10)
               "mov %%rax, %%cr4;"
               : : : "rax");

  // set NE in cr0 and reset x87 fpu
  asm volatile("fninit;"
               "mov %%cr0, %%rax;"
               "or $0b100000, %%rax;"        // CR0.NE (bit 5)
               "mov %%rax, %%cr0;"
               : : : "rax");

  // Do AVX stuff under certain conditions (qemu and prolly other stuff fake
  // not having support but all AVX instructions succeed)
  uint32_t eax = 1, ebx = 0, ecx = 0, edx = 0;
  cpuid(&eax, &ebx, &ecx, &edx);
  if (ecx & (1 << 26)) {                    // XSAVE
    uint64_t cr4;
    asm volatile("mov %%cr4, %0" : "=r"(cr4));
    cr4 |= (uint32_t)1 << 18;                // CR4.OSXSAVE
    asm volatile("mov %0, %%cr4" : : "r"(cr4));
    if (ecx & (1 << 28)) {                  // AVX
      uint32_t xcr0_lo = 0x7; // x87 (bit 0), SSE (bit 1), AVX (bit 2)
      uint32_t xcr0_hi = 0;
      asm volatile("xsetbv" ::"c"(0), "a"(xcr0_lo), "d"(xcr0_hi));
    }
  }
}

cpu/sse.asm có một bản asm cũ (asm_enable_SSE) làm phần CR0/CR4; nay lời gọi tới nó bị comment, phần đó chuyển thành inline asm như trên.

3. Kernel không bao giờ dùng FPU

make
# src/kernel/Makefile
CFLAGS = -m64 -g -c -ffreestanding -Wall -Werror -fcommon -Iinclude/ ... -fPIE -mno-80387 \
    -mno-mmx \
    -mno-sse \
    ...
    -mno-sse2 \
    -mno-red-zone -fno-stack-protector \

Compiler bị cấm sinh lệnh x87/MMX/SSE trong code kernel. Nhờ vậy, khi một ngắt hay syscall đưa CPU vào kernel, thanh ghi FPU vẫn nguyên là của task user vừa chạy, và kernel không phải lưu chúng ở mỗi lần vào. Chỉ lúc đổi task mới phải lưu.

4. Vùng lưu trong mỗi task

c
// include/task.h
  __attribute__((aligned(16))) uint8_t fpuenv[512];
  uint32_t                             mxcsr;

// multitasking/task.c (taskCreate)
  memset(target->fpuenv, 0, 512);
  ((uint16_t *)target->fpuenv)[0] = 0x37f;     // x87 FCW: all exceptions masked, 64-bit precision
  target->mxcsr = 0x1f80;                      // MXCSR: all SSE exceptions masked, round to nearest

512 byte căn 16 đúng là định dạng của fxsave. FCW 0x37f và MXCSR 0x1f80 là giá trị mặc định sau fninit và sau reset: task mới bắt đầu với FPU "sạch".

5. Lưu và nạp khi đổi task

c
// multitasking/schedule.c
  // Save & load appropriate FPU state
  if (!old->kernel_task) {
    asm volatile(" fxsave %0 " ::"m"(old->fpuenv));
    asm("stmxcsr (%%rax)" : : "a"(&old->mxcsr));
  }

  if (!next->kernel_task) {
    asm volatile(" fxrstor %0 " ::"m"(next->fpuenv));
    asm("ldmxcsr (%%rax)" : : "a"(&next->mxcsr));
  }
  • Chỉ task user mới lưu/nạp: kernel thread không dùng FPU (mục 3).
  • Lưu mỗi lần đổi task (eager), không đợi task chạm FPU (lazy, dùng CR0.TS để bắt lần chạm đầu). Đơn giản và an toàn, đổi lại tốn một fxsave/fxrstor mỗi tick.
  • fork chép fpuenv sang task con (sau khi fxsave trạng thái hiện tại); xử lý signal lưu và nạp lại vùng này quanh handler signal (syscalls/signals.c).

Tự kiểm tra

Bốn câu.

Kernel quên đặt CR4.OSFXSR. Một chương trình C chỉ làm phép cộng double chạy được không?

Không. x86-64 tính double bằng SSE (addsd), và mọi lệnh SSE là #UD khi OSFXSR = 0. Chỉ có x87 chạy được.

Vì sao vùng fxsave phải căn 16 byte, còn xsave căn 64?

Đặc tả lệnh yêu cầu vậy: địa chỉ không căn đúng gây #GP. Vùng fxsave là định dạng cố định 512 byte; vùng xsave có header ở offset 512 và các thành phần mở rộng, cỡ tuỳ XCR0.

XCR0 = 7 nhưng scheduler dùng fxsave. Chương trình nào bị ảnh hưởng?

Chương trình dùng thanh ghi YMM (lệnh AVX 256 bit), khi có task khác cũng dùng YMM chạy xen giữa. Nửa cao YMM không được lưu, nên mang giá trị của task chạy sau cùng. Chương trình chỉ dùng SSE 128 bit không bị.

Lưu FPU kiểu eager (mỗi lần đổi task) tốn gì, và lazy (dùng CR0.TS) tiết kiệm gì?

Eager: một fxsave + fxrstor (vài trăm byte) mỗi lần đổi task user, kể cả khi task không dùng FPU. Lazy: đặt CR0.TS khi đổi task; lần đầu task chạm FPU gây #NM, handler mới lưu của người cũ và nạp của người mới. Tiết kiệm khi ít task dùng FPU, nhưng phức tạp hơn và có lỗ hổng rò rỉ thông tin trên CPU có thực thi suy đoán (LazyFP, 2018).

Đọc thêm

Câu hỏi của dàn ý cũ, chỗ lệch giữa phần bật và phần lưu, và chỗ tra trong spec.

Câu hỏi mở (đã trả lời)

  • Lưu FPU kiểu eager hay lazy? Eager, mỗi lần đổi giữa các task user.
  • Có bật AVX không? Có, nếu CPUID báo XSAVE và AVX: CR4.OSXSAVE và XCR0 = 7.
  • Kernel có dùng SSE? Không, biên dịch với -mno-sse -mno-sse2 -mno-80387 -mno-mmx.

Bật AVX nhưng không lưu nửa cao YMM

initiateSSE() bật AVX (XCR0 = 7), nhưng schedule() lưu bằng fxsave, lệnh chỉ biết x87 và XMM. Nửa cao 128 bit của YMM0–15 không được lưu khi đổi task. Lab 0x0b đo được: hai task cùng dùng YMM0, task bị đổi ra thấy nửa cao mang giá trị của task kia ở 40/40 lần kiểm. Sửa: lưu bằng xsave/xrstor với vùng đủ cỡ (CPUID leaf 0xD, 832 byte với XCR0 = 7) căn 64 byte, như bản DEMO=-DXSAVE của lab (0 lỗi). Code tạo task và fork cũng phải chép đủ vùng mới.

MXCSR được lưu hai lần

Vùng fxsave đã chứa MXCSR ở offset 24, và fxrstor nạp lại nó. stmxcsr/ldmxcsr riêng với trường mxcsr là thừa (vô hại). Task mới có MXCSR = 0 ở offset 24 của vùng lưu (chỉ đặt mxcsr = 0x1f80), nên fxrstor nạp MXCSR = 0 (mọi ngoại lệ SSE được mở) rồi ldmxcsr sửa lại ngay sau đó.
