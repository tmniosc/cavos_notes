Bài 11 - PS/2 Keyboard & Mouse

Status doneTags step, input, ps2, 8042

Hàm: fsMount("/dev/", CONNECTOR_DEV, 0, 0), initiateKb() (drivers/kb.c), initiateMouse() (drivers/mouse.c) · Phụ thuộc: IRQ qua I/O APIC từ Bài 10 - APIC & Timer, handler từ Bài 9 - IDT & Interrupts

Mục đích

Kernel bắt đầu nghe người dùng: bàn phím và chuột.

Đến Bài 10, kernel chỉ in ra. Bài này cho nó nhận input qua controller 8042: phím gõ thành ký tự cho chương trình đang read(), và mọi phím, mọi cú di chuột thành sự kiện trong file /dev/input/eventN. Đây cũng là driver đầu tiên dùng IRQ thật của thiết bị, đúng chuỗi của Bài 9 và 10: thiết bị báo ngắt → handler đọc cổng → dữ liệu tới người cần. Bài 12 cần nó, vì task chờ phím phải được đánh thức khi phím tới.

Nói thật đơn giản

Bàn phím và chuột không nói chuyện thẳng với CPU. Giữa chúng có một hộp thư (chip 8042) với một khe duy nhất (cổng 0x60) và một tấm bảng báo hiệu (cổng 0x64). Mỗi lần bạn bấm hay nhả một phím, bàn phím bỏ vào khe một mã số (scancode), hộp thư rung chuông (IRQ1) cho CPU biết có thư. Chuột cũng bỏ thư vào cùng khe đó, nhưng rung chuông khác (IRQ12), và mỗi "lá thư" của chuột gồm 3 mảnh.

Mã số không phải chữ cái. Driver phải tự nhớ "Shift đang giữ không, Caps Lock đang bật không" rồi tra bảng ra chữ. Sau đó cavOS gửi kết quả theo hai ngả: chữ cái cho chương trình đang chờ đọc một dòng (như bash), và một bản ghi "phím số 35 vừa được nhấn" cho chương trình đọc thiết bị trực tiếp (như X server hay game).

Cần biết trước

Ba ý mới; cổng I/O, IRQ, I/O APIC đã gặp ở các bài trước.

  • Controller 8042 và hai cổng. Chip điều khiển bàn phím của PC, nay là một khối trong chipset (QEMU giả lập nó). Nó có hai cổng PS/2: cổng 1 cho bàn phím, cổng 2 (aux) cho chuột. CPU chỉ thấy hai cổng I/O: 0x60 (dữ liệu: đọc byte từ thiết bị, ghi byte gửi thiết bị) và 0x64 (đọc là thanh ghi trạng thái, ghi là lệnh cho chính controller). Bit 0 của trạng thái = "có byte chờ ở 0x60", bit 1 = "controller chưa nhận xong byte trước, đừng ghi". Đọc sâu: OSDev "8042 PS/2 Controller" (xem Danh mục tài liệu).
  • Scancode, make/break, set 1 và set 2. Bàn phím gửi một mã khi nhấn (make) và một mã khi nhả (break). Có nhiều bảng mã: bàn phím ngày nay gửi set 2 (nhả = F0 + mã nhấn), nhưng 8042 mặc định dịch sang set 1 cũ của IBM PC/XT (nhả = mã nhấn | 0x80). Phím thêm vào sau (mũi tên, Ctrl phải…) có tiền tố E0. cavOS chỉ hiểu set 1.
  • evdev và struct input_event. Cách Linux đưa input cho userspace: mỗi thiết bị là một file /dev/input/eventN; read() trả các bản ghi {thời gian, type, code, value}, ví dụ EV_KEY KEY_H 1 (H nhấn), EV_REL REL_X -3 (chuột sang trái 3), và EV_SYN để đánh dấu hết một nhóm. cavOS giả lập đúng giao diện này để chạy được chương trình viết cho Linux.
  • Đã gặp: cổng I/O và inb/outb ở Bài 2; IRQ, vector, handle_interrupt, EOI ở Bài 9; ioApicRedirect, cấp vector 32 + chỉ số, IRQ ISA là edge/active-high ở Bài 10.

Đọc code cavOS

Ba bước trong _start(): dựng /dev/, bật bàn phím, bật chuột; rồi hai handler IRQ đẩy dữ liệu tới người đọc.

File: entry/kernel.c, drivers/kb.c, include/kb.h, drivers/mouse.c, include/mouse.h, filesystems/dev/dev_event.c, filesystems/dev/dev_controller.c, syscalls/io.c (cavOS 2ba0edb).

2. Controller 8042: cổng, trạng thái, byte cấu hình

cavOS không có file riêng cho controller; kb.c và mouse.c dùng thẳng số 0x60/0x64. Các bit nó dùng:

Thanh ghi trạng thái (đọc 0x64)NghĩacavOS dùng ở
bit 0 OBFcó byte chờ đọc ở 0x60kbRead, mouseWait(0) (MOUSE_BBIT)
bit 1 IBFcontroller chưa lấy byte vừa ghi; phải chờ về 0 rồi mới ghi tiếpkbWrite, mouseWait(1) (MOUSE_ABIT)
bit 2system flag (đã qua POST)không
bit 3byte ghi cuối là lệnh (0x64) hay dữ liệu (0x60)không
bit 5byte ở 0x60 đến từ cổng 2 (chuột)không (MOUSE_F_BIT 0x20 khai nhưng không dùng)
bit 6, 7lỗi timeout, lỗi paritykhông
Byte cấu hình (lệnh 0x20 đọc, 0x60 ghi)Nghĩa
bit 0cổng 1 có byte → bắn IRQ1
bit 1cổng 2 có byte → bắn IRQ12 (initiateMouse bật bit này)
bit 4, 5tắt clock cổng 1, cổng 2 (lệnh 0xAE/0xA8 xoá chúng)
bit 6dịch scancode set 2 → set 1 cho cổng 1

Các lệnh controller cavOS gửi: 0xAE bật cổng 1, 0xA8 bật cổng 2, 0x20/0x60 đọc/ghi byte cấu hình, 0xD4 "byte kế tiếp ghi vào 0x60 là cho chuột". Không có tự kiểm tra (0xAA), không tắt cổng hay xả bộ đệm trước khi cấu hình như OSDev hướng dẫn: cavOS tin firmware đã để controller dùng được. Lab 0x06 đọc thử: SeaBIOS để lại byte cấu hình 0x61 (IRQ1 bật, đang dịch, chuột tắt), OVMF để 0x67.

3. initiateKb(): bốn dòng thật sự chạm phần cứng

c
// drivers/kb.c
void initiateKb() {
  kbEvent = devInputEventSetup("PS/2 Keyboard");     // tạo /dev/input/event0
  kbEvent->inputid.bustype = 0x05;   // BUS_PS2
  kbEvent->inputid.vendor = 0x045e;  // Microsoft
  kbEvent->inputid.product = 0x0001; // Generic MS Keyboard
  kbEvent->inputid.version = 0x0100; // Basic MS Version
  kbEvent->eventBit = kbEventBit;    // trả lời ioctl EVIOCGBIT

  uint8_t targIrq = ioApicRedirect(1, false);
  registerIRQhandler(targIrq, kbIrq);
  kbReset();
  kbWrite(0x64, 0xae);
  inportb(0x60);
}
  • ioApicRedirect(1, false) (Bài 10): IRQ 1 không có override trên QEMU → GSI 1 → chân 1, edge, active-high. Vector là 0x22, vì PIT đã lấy 0x20 và LAPIC timer 0x21.
  • kbWrite(0x64, 0xae): chờ IBF = 0 rồi gửi lệnh "bật cổng 1".
  • inportb(0x60): đọc bỏ một byte. Không phải cho vui: 8042 giữ dây IRQ1 ở mức cao chừng nào bộ đệm còn byte, còn I/O APIC bắt cạnh lên. Một byte cũ còn nằm đó thì sẽ không có cạnh mới, không có IRQ nào nữa. Đọc nó đi là hạ dây xuống.
  • Không có dòng nào chọn scancode set hay bật bit dịch, không bật bit 0 (IRQ1) của byte cấu hình. cavOS dựa vào firmware: Lab 0x06 xác nhận SeaBIOS và OVMF đều để bàn phím ở set 2, controller đang dịch, IRQ1 bật.

4. kbIrq() → handleKbEvent(): từ scancode ra ký tự

c
uint8_t kbRead() {
  while (!(inportb(0x64) & 1))   // chờ OBF
    ;
  return inportb(0x60);
}

char handleKbEvent() {
  uint8_t scanCode = kbRead();
  kbEvdevGenerate(scanCode);           // ngả 1: sự kiện evdev

  // Shift checks
  if (shifted == 1 && scanCode & 0x80) {
    if ((scanCode & 0x7F) == 42) {     // nhả Shift trái (0xAA)
      shifted = 0;
      return 0;
    }
  }
  if (scanCode < sizeof(characterTable) && !(scanCode & 0x80)) {   // chỉ mã nhấn
    char character = (shifted || capsLocked) ? shiftedCharacterTable[scanCode]
                                             : characterTable[scanCode];
    if (character != 0)
      return character;
    switch (scanCode) {
    case SCANCODE_ENTER: return CHARACTER_ENTER;   // 28 -> '\n'
    case SCANCODE_BACK:  return CHARACTER_BACK;    // 14 -> '\b'
    case SCANCODE_SHIFT: shifted = 1; break;       // 42
    case SCANCODE_CAPS:  capsLocked = !capsLocked; break;   // 58
    }
  }
  return 0;
}
  • characterTable là mảng 140 phần tử, chỉ số = scancode set 1: [0x1E] = 'a', [0x02] = '1'… shiftedCharacterTable cùng vị trí nhưng là chữ hoa và ký hiệu. Mã nhả (bit 7 bật) không tra bảng.
  • Trạng thái chỉ có hai biến: shifted (chỉ Shift trái, scancode 42) và capsLocked. Ctrl, Alt, Shift phải không được theo dõi ở ngả ký tự.
  • Comment trong source nói rõ đây là phần tác giả không định sửa: "No, I will not fix/improve the rest, idc about the kernel shell". Các chỗ sai thấy được ở Đọc thêm.

Sau đó kbIrq giao ký tự cho task đang chờ (mục 7).

5. kbEvdevGenerate(): sự kiện kiểu Linux

c
void kbEvdevGenerate(uint8_t raw) {
  uint8_t index = 0;
  bool    clicked = false;
  if (raw <= 0x58) {          // mã nhấn
    clicked = true;
    index = raw;
  } else if (raw <= 0xD8) {   // mã nhả = nhấn | 0x80
    clicked = false;
    index = raw - 0x80;
  } else
    return;                   // 0xE0, 0xFA ...
  ...
  uint8_t evdevCode = evdevTable[index];
  bool oldstate = bitmapGenericGet(evdevInternal, index);
  if (!oldstate && clicked) {         // nhấn
    inputGenerateEvent(kbEvent, EV_KEY, evdevCode, 1);
    lastPressed = evdevCode;
  } else if (oldstate && clicked) {   // giữ lâu, bàn phím tự gửi lại: lặp
    if (evdevCode != lastPressed)
      return;
    inputGenerateEvent(kbEvent, EV_KEY, evdevCode, 2);
  } else if (oldstate && !clicked) {  // nhả
    inputGenerateEvent(kbEvent, EV_KEY, evdevCode, 0);
  }
  inputGenerateEvent(kbEvent, EV_SYN, SYN_REPORT, 0);
  bitmapGenericSet(evdevInternal, index, clicked);
}
  • evdevTable[89] viết bằng tên KEY_ESC, KEY_1… nhưng giá trị số của các tên đó trong Linux trùng scancode set 1 từ 1 tới 88: KEY_H = 35 = 0x23. Chỗ khác duy nhất là cavOS đổi các phím keypad 8/4/6/2/0/. thành KEY_UP/LEFT/RIGHT/DOWN/INSERT/DELETE.
  • Tiền tố 0xE0 bị bỏ, nên mũi tên lên (E0 48) và keypad 8 (48) cùng ra KEY_UP: cách cavOS cho mũi tên chạy mà không cần xử lý tiền tố.
  • value 1/2/0 = nhấn/lặp/nhả, đúng quy ước evdev. Bitmap evdevInternal nhớ phím nào đang giữ để phân biệt "nhấn" với "lặp".

6. initiateMouse() và mouseIrq()

c
void initiateMouse() {
  mouseEvent = devInputEventSetup("PS/2 Mouse");     // /dev/input/event1
  ...
  // enable the auxiliary mouse
  mouseWait(1);
  outportb(0x64, 0xA8);

  // enable interrupts
  mouseWait(1);
  outportb(0x64, 0x20);              // đọc byte cấu hình
  sleep(100);
  mouseWait(0);
  sleep(100);
  uint8_t status;
  status = (inportb(0x60) | 2);      // bật bit 1: IRQ12
  mouseWait(1);
  outportb(0x64, 0x60);              // ghi byte cấu hình
  mouseWait(1);
  outportb(0x60, status);

  // default settings
  mouseWrite(0xF6);                  // 0xD4 rồi 0xF6 qua mouseWrite
  mouseRead();                       // ACK 0xFA

  // enable device
  mouseWrite(0xF4);                  // bật gửi dữ liệu
  mouseRead();

  // irq handler
  uint8_t targIrq = ioApicRedirect(12, false);
  registerIRQhandler(targIrq, mouseIrq);
}
  • mouseWait(type) chờ bit 0 lên 1 (type 0) hoặc bit 1 về 0 (type 1) tối đa MOUSE_TIMEOUT = 100000 vòng, hết giờ thì đi tiếp không báo gì.
  • Chuột chỉ gửi gói sau lệnh 0xF4 (enable data reporting). Mỗi lệnh gửi chuột phải qua 0xD4 trước, nếu không byte sẽ tới bàn phím.
  • Không bật chế độ IntelliMouse (bánh xe, gói 4 byte), nên gói luôn 3 byte.
  • Lúc lệnh 0x20 chạy, IRQ1 đã được nối và ngắt đang bật. Lab 0x06 cho thấy kbIrq giành mất byte cấu hình: xem Đọc thêm.
c
void mouseIrq() {
  uint8_t byte = mouseRead();
  if (mouseCycle == 0)      mouse1 = byte;
  else if (mouseCycle == 1) mouse2 = byte;
  else {
    int mouse3 = byte;
    do {
      assert(mouse1 & (1 << 3));          // byte đầu phải có bit 3
      int x = mouse2;
      int y = mouse3;
      if (x && mouse1 & (1 << 4)) x -= 0x100;   // đổi dấu 9 bit
      if (y && mouse1 & (1 << 5)) y -= 0x100;
      gx += x;  gy += -y;  ... kẹp gx, gy trong fb.width, fb.height
      bool click = mouse1 & (1 << 0);
      bool rclick = mouse1 & (1 << 1);
      ... EV_KEY BTN_LEFT / BTN_RIGHT khi nút đổi trạng thái
      inputGenerateEvent(mouseEvent, EV_REL, REL_X, x);
      inputGenerateEvent(mouseEvent, EV_REL, REL_Y, -y);   // evdev: dương = đi xuống
      inputGenerateEvent(mouseEvent, EV_SYN, SYN_REPORT, 0);
    } while (0);
  }
  mouseCycle++;
  if (mouseCycle > 2) mouseCycle = 0;
}

Mỗi IRQ12 mang một byte; gói có ba byte nên handler đếm mouseCycle 0, 1, 2. Nút giữa (bit 2) không được báo. gx/gy được tính nhưng không gửi đi: dòng EV_ABS đã bị comment, chỉ có EV_REL.

7. Từ IRQ tới người đọc: /dev/input/eventN và /dev/stdin

Một phím đi hai ngả, chuột đi một ngả:

Ngả evdev (filesystems/dev/dev_event.c). devInputEventSetup(name) lấy ô tiếp theo trong mảng devInputEvents[MAX_EVENTS = 8], cấp một CircularInt 16384 byte, và thêm file eventN vào thư mục /dev/input/ của fakefs. Bàn phím khởi tạo trước nên là event0, chuột là event1.

c
void inputGenerateEvent(DevInputEvent *item, uint16_t type, uint16_t code, int32_t value) {
  if (atomicRead64(&item->timesOpened) == 0)
    return;                                   // không ai mở file: bỏ
  struct input_event event = {0};
  event.sec = timerTicks / 1000;              // tick 1 ms của Bài 10
  event.usec = (timerTicks % 1000) * 1000;
  event.type = type;  event.code = code;  event.value = value;
  // todo out of sync stuff
  assert(CircularIntWrite(&item->deviceEvents, (void *)&event,
                          sizeof(struct input_event)) == sizeof(struct input_event));
}

Phía đọc, devInputEventRead lặp CircularIntRead tới khi có dữ liệu; mở bằng O_NONBLOCK thì trả EWOULDBLOCK ngay. CircularIntWrite chỉ được gọi trong ngữ cảnh ngắt (nó assert(!checkInterrupts())), nên chỉ có một người ghi và không cần khoá. Các ioctl (EVIOCGNAME, EVIOCGBIT qua kbEventBit/ mouseEventBit…) cho chương trình biết thiết bị có những phím, trục nào.

Ngả ký tự (syscalls/io.c và kb.c). /dev/stdin dùng handler stdio; run() trong utilities/shell/shell.c mở /dev/stdin và /dev/stdout cho task mới. Khi task gọi read() trên đó:

  1. readHandler cấp một buffer và gọi kbTaskRead(currentTask->id, buff, limit, true): ghi kbBuff, kbMax, kbTaskId, đặt task về TASK_STATE_WAITING_INPUT, rồi handControl() nhường CPU cho tới khi task được đánh thức.
  2. Mỗi IRQ1, kbIrq bỏ qua nếu !kbBuff || !out || !tasksInitiated. Còn lại: Enter ở chế độ ICANON thì kbFinaliseStream() (ghi số byte vào task->tmpRecV, đặt task READY); Backspace xoá một ký tự; ký tự thường qua kbChar(): in ra màn hình nếu bật ECHO, thêm vào kbBuff, và nếu không ICANON thì trả ngay từng ký tự.
  3. Task chạy lại, readHandler chép dữ liệu ra, thêm '\n' ở chế độ ICANON.

Chỉ có một kbBuff cho cả hệ thống, nên tại một lúc chỉ một task đọc bàn phím; task khác gọi kbTaskRead sẽ quay chờ kbIsOccupied(). Việc đánh thức task thuộc scheduler: Bài 12. VFS, fakefs và fsMount: Bài 15.

Bàn phím và chuột cùng đưa byte ra cổng 0x60. Handler biết byte là của ai bằng cách nào?

Bằng IRQ: byte từ cổng 1 bắn IRQ1, từ cổng 2 bắn IRQ12, nên mỗi handler chỉ chạy cho thiết bị của nó. Thanh ghi trạng thái cũng nói điều đó qua bit 5 (1 = chuột), nhưng cavOS không đọc bit này.

Firmware nào đó để bit 6 (dịch) của byte cấu hình bằng 0. Gõ chữ a trên cavOS thì sao?

Bàn phím gửi set 2 thô: a nhấn là 0x1C, mà trong bảng set 1 của cavOS 0x1C là Enter. Nhả là F0 1C, thêm một Enter nữa. Lab 0x06 tắt bit này bằng F2 và thấy đúng như vậy.

Vì sao initiateKb đọc bỏ một byte ở 0x60 ngay sau khi bật cổng 1?

I/O APIC nối IRQ1 kiểu edge. 8042 giữ dây IRQ ở mức cao khi còn byte trong bộ đệm, nên một byte cũ làm dây không bao giờ có cạnh lên mới: bàn phím im lặng mãi. Đọc nó đi là hạ dây xuống.

Một chương trình mở /dev/input/event1 rồi không bao giờ read(). Di chuột mãi thì chuyện gì xảy ra?

Mỗi gói sinh 3–5 bản ghi 24 byte vào CircularInt 16384 byte. Khoảng 680 bản ghi thì đầy, CircularIntWrite trả 0 và assert trong inputGenerateEvent làm kernel panic. Nếu chưa ai mở file thì không sao: sự kiện bị bỏ ngay từ đầu.

Vì sao mouseIrq phải đếm mouseCycle, và điều gì xảy ra nếu mất một byte?

Mỗi IRQ12 chỉ mang một byte, gói có ba. Mất một byte thì byte thứ hai của gói sau bị coi là byte đầu; nếu nó không có bit 3, assert(mouse1 & (1 << 3)) làm panic, còn nếu có thì mọi gói sau đều lệch. cavOS không có bước đồng bộ lại.

Câu hỏi mở (đã trả lời)

  • Scancode set 1 vs 2, translation? Bàn phím (thật và QEMU) mặc định gửi set 2. Bit 6 của byte cấu hình 8042 bật thì controller dịch sang set 1 trước khi CPU đọc, kể cả câu trả lời của lệnh 0xF0 0x00 (2 → 0x41). cavOS chỉ có bảng set 1 và không tự bật bit dịch; nó chạy được vì SeaBIOS (0x61) và OVMF (0x67) đều để bit 6 bật. Lab 0x06 đo cả hai và tắt thử bit này.
  • USB legacy emulation ảnh hưởng gì trên QEMU? Không: trên máy q35/pc mặc định, bàn phím và chuột là thiết bị PS/2 giả lập trực tiếp trong 8042 (info mice báo QEMU PS/2 Mouse), không có lớp USB nào. Trên máy thật chỉ có bàn phím USB, firmware có thể giả làm 8042 ("USB legacy support", thường bằng SMM) cho tới khi OS nhận quyền điều khiển USB controller. cavOS không có driver USB nào (grep xhci/ehci/uhci trong src/kernel không ra gì), nên trên máy như vậy nó phụ thuộc hoàn toàn vào lớp giả lập đó. Comment "should work with USB mice too" ở đầu mouse.c chỉ đúng theo nghĩa này.
  • Hàm initiatePS2() của dàn ý cũ không tồn tại; cavOS tách thành initiateKb() và initiateMouse().
  • Gói 3 hay 4 byte? 4 byte chỉ khi bật IntelliMouse (bánh xe) bằng dãy "set sample rate 200, 100, 80" rồi đọc ID thiết bị = 3. cavOS không làm, nên luôn 3 byte, không có bánh xe.

Lỗi đổi ký tự trong handleKbEvent (drivers/kb.c)

Lab 0x06 tính mỗi ký tự theo cả luật cavOS (chép nguyên hàm) và luật đúng, rồi in khi khác nhau. Output thật:

text
[irq1]  0x64=0x1d 0x60=0x2  make  key -> '1'   [cavOS rule gives '!']
[irq1]  0x64=0x1d 0x60=0x2e  make  key -> 'c'   [cavOS rule gives 'C']
[irq1]  0x64=0x1d 0x60=0x3  make  key -> '@'   [cavOS rule gives '2']
[irq1]  0x64=0x1d 0x60=0x2d  make  key -> 'X'   [cavOS rule gives 'x']
[irq1]  0x64=0x1d 0x60=0x50  make  Down   [cavOS rule gives ESC]
  • Caps Lock chọn cả bảng Shift: (shifted || capsLocked) ? shiftedCharacterTable[...]. Caps + 1 ra !, Caps + [ ra {. Caps Lock thật chỉ đổi chữ cái.
  • Caps + Shift vẫn ra chữ hoa: phép || không cho hai cái triệt tiêu nhau (với chữ cái phải là XOR).
  • Không có Shift phải: chỉ scancode 42 (SCANCODE_SHIFT) được xử lý; 54 (0x36) rơi vào switch mà không có case.
  • Mũi tên xuống thành ESC: tiền tố 0xE0 bị bỏ qua (nó có bit 7), byte sau 0x50 tra characterTable[0x50], mà ô đó là 0x1B. Bảng còn vài ô lạ khác: [0x5B] = 0x0E, [0x5C] = 0x1C, [0x65] = '/', [0x78..0x82] và [0x8B] chứa các số 0x1E…0x2C. Không rõ chủ ý; chỉ ghi lại hậu quả quan sát được.
  • Ngả evdev không bị các lỗi này: nó báo mã phím, không báo ký tự. Chương trình đọc /dev/input/event0 tự xử lý Shift và Caps.

Byte cấu hình bị IRQ1 lấy mất trong initiateMouse

Thứ tự trong _start() là initiateKb() rồi initiateMouse(), và ngắt đã bật. Khi initiateMouse gửi 0x20, controller đặt byte cấu hình vào 0x60 và bắn IRQ1 (bit 0 của chính byte đó đang bật). kbIrq chạy trong lúc sleep(100), đọc byte và coi là scancode. Lab 0x06 giữ đúng thứ tự này:

text
[mouse] config read after 0xA8 = 0x41 (IRQ1=1 IRQ12=0 SYS=0 port1-clock-off=0 port2-clock-off=0 translate=1)
[early] [irq1]  0x64=0x1d 0x60=0x41  make  F7
...
##### harness: sendkey f7
[irq1]  0x64=0x1d 0x60=0x41  make  F7
[irq1]  0x64=0x1d 0x60=0xc1  break F7
        /dev/input/event0: EV_KEY code 65=0, SYN
  • Byte cấu hình bị hiểu là phím. SeaBIOS: 0x41 = F7 nhấn (TCG và KVM như nhau). OVMF: 0x47 = keypad 7 nhấn.
  • mouseRead vẫn ra đúng giá trị là nhờ may. mouseWait(0) hết giờ (bộ đệm đã rỗng), rồi inportb(0x60) trả lại byte cuối, vì QEMU giữ byte đã đọc. Một controller trả giá trị khác khi rỗng sẽ làm initiateMouse ghi một byte cấu hình sai.
  • Phím bị kẹt trong bitmap evdev. Lúc boot chưa ai mở event0 nên inputGenerateEvent bỏ sự kiện, nhưng bitmapGenericSet vẫn đánh dấu F7 đang giữ. Lần nhấn F7 thật đầu tiên rơi vào nhánh "lặp" với evdevCode != lastPressed nên không sinh sự kiện nào; chương trình chỉ thấy nhả (code 65=0) mà không thấy nhấn.
  • Đổi thứ tự (chuột trước bàn phím) thì hết: Lab 0x06 đã chạy thử, không còn dòng [early]. Cách khác: che IRQ1 hoặc tắt ngắt quanh đoạn đọc byte cấu hình.

Điểm yếu của mouseIrq (drivers/mouse.c)

  • Sự kiện "nhả nút phải" thừa. bool clickedRight = true; lúc khai báo, nên gói đầu tiên (nút phải không giữ) sinh EV_KEY BTN_RIGHT 0. Lab 0x06, gói đầu: /dev/input/event1: EV_KEY BTN_RIGHT=0, EV_REL REL_X=+10, …. clickedLeft thì khởi tạo false.
  • Không đồng bộ lại gói. assert(mouse1 & (1 << 3)) panic khi byte đầu không có bit 3; không có cách nào khác để bắt lại nhịp. Dòng kiểm bit tràn (6, 7) đã bị comment. (Không xảy ra trong các lần chạy của lab: mouse resyncs=0.)
  • Đổi dấu thiếu một trường hợp. if (x && mouse1 & (1 << 4)) x -= 0x100;: byte bằng 0 mà bit dấu bật nghĩa là −256, nhưng điều kiện x && để nó thành 0. Chỉ xảy ra khi chuột báo đúng −256; QEMU chia bước lớn thành nhiều gói ±127 nên không gặp.
  • Nút giữa (bit 2) bị bỏ, dù gói có báo.

Ring evdev đầy là panic (filesystems/dev/dev_event.c)

inputGenerateEvent bọc lệnh ghi trong assert(CircularIntWrite(...) == sizeof(struct input_event)), có comment // todo out of sync stuff. CircularIntWrite trả 0 khi không đủ chỗ (circular.c), và _assert gọi panic() (cpu/system.c). Một chương trình mở /dev/input/eventN mà ngừng đọc (bị treo, bị dừng bằng tín hiệu) sẽ làm kernel panic sau khoảng 16384 / 24 ≈ 680 bản ghi, tức vài trăm lần gõ phím hay di chuột. Linux xử lý chỗ này bằng cách bỏ sự kiện cũ và báo SYN_DROPPED. (Chưa chạy thử trên cavOS; kết luận từ đọc code.)

Ánh xạ spec

  • 8042 controller, PS/2 protocol (OSDev). Trang "8042 PS/2 Controller": cổng 0x60/0x64, thanh ghi trạng thái, byte cấu hình (bit 0/1 IRQ, 4/5 clock, 6 translation), lệnh 0x20/0x60/0xA7/0xA8/0xAA/0xAD/0xAE/0xD4, trình tự khởi tạo đầy đủ. Danh sách: Danh mục tài liệu.
  • OSDev "PS/2 Keyboard": lệnh 0xF0 (get/set scancode set), 0xF4, 0xFF, ACK 0xFA; bảng scancode set 1 và set 2, tiền tố E0, F0.
  • OSDev "Mouse Input" / "PS/2 Mouse": lệnh 0xF6, 0xF4, định dạng gói 3 byte, IntelliMouse 4 byte.
  • Linux include/uapi/linux/input-event-codes.h và input.h: EV_KEY, EV_REL, EV_SYN, mã KEY_*, BTN_LEFT (0x110), struct input_event, ioctl EVIOCG*. cavOS chép các hằng này vào include/linux_event_codes.h.
