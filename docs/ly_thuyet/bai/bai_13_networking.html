Mục đích

Cho kernel gửi và nhận gói tin, và để một thư viện lo phần "nói đúng ngôn ngữ mạng".

cavOS không tự viết TCP/IP. Nó dùng lwIP (lightweight IP), một thư viện TCP/IP nhỏ viết cho hệ nhúng, và viết phần "keo" nối lwIP với kernel: thread, semaphore, đồng hồ, và hai đường đi của frame (card → lwIP khi nhận, lwIP → card khi gửi). Bài này đọc phần keo đó và các lớp giao thức mà nó chở. Phần phần cứng (PCI, card E1000) là Bài 14; trong _start(), initiateNetworking() chạy ngay trước initiatePCI().

Nói thật đơn giản

Gửi một gói tin giống gửi một lá thư bỏ trong nhiều lớp phong bì. Phong bì trong cùng ghi "giao cho chương trình số 67" (UDP). Phong bì ngoài hơn ghi "gửi tới máy 10.0.2.2" (IP). Phong bì ngoài cùng ghi "đưa cho cái card mạng có số hiệu 52:55:0a:00:02:02" (Ethernet). Mỗi trạm chỉ đọc lớp phong bì của mình.

Máy mới bật thì chưa có địa chỉ nhà. Nó hét lên cả xóm "ai cấp địa chỉ cho tôi với" (DHCP), rồi hỏi "ai là 10.0.2.2, số card của bạn là gì" (ARP). cavOS giao hết việc viết và đọc phong bì cho lwIP. Phần cavOS tự làm là bưu tá: nhận thư từ card, xếp vào hàng (netQueue), và một người giúp việc (thread helper) mang từng lá cho lwIP đọc.

Cần biết trước

Ba ý mạng cơ bản; thread và handler ngắt đã có ở các bài trước.

  • Các lớp và frame. Trên dây Ethernet đi các frame: 6 byte MAC đích, 6 byte MAC nguồn, 2 byte ethertype (0x0800 IPv4, 0x0806 ARP), rồi dữ liệu. Gói IPv4 có header 20 byte (IP nguồn, IP đích, số giao thức: 17 = UDP, 1 = ICMP). UDP thêm 8 byte (cổng nguồn, cổng đích). Mỗi lớp bọc lớp trong.
  • Byte order mạng. Mọi số nhiều byte trên dây là big-endian (byte cao trước). x86 là little-endian, nên mỗi trường 16/32 bit phải đảo byte khi ghi và khi đọc. cavOS có switch_endian_16; lwIP có htons/ntohs.
  • DHCP và ARP. DHCP (UDP cổng 68 → 67) xin IP: DISCOVER → OFFER → REQUEST → ACK. ARP đổi IP thành MAC: "ai có 10.0.2.2?" gửi broadcast, máy đó trả lời MAC của nó. Có MAC rồi mới gửi được frame IP tới máy đó.
  • Đã gặp: thread kernel, handControl(), thread helper kernelHelpEntry ở Bài 12; handler ngắt chạy với IF tắt ở Bài 9.

1. Vị trí trong _start()

// entry/kernel.c:_start()
  initiateTasks();
  initiateKernelThreads();

  fsMount("/", CONNECTOR_AHCI, 0, 1);
c
// drivers/nics/nic_controller.c
void initiateNetworking() {
  // start off with no first NIC and no selected one
  // rest on device-specific initialization
  selectedNIC = 0;
  debugf("[networking] Ready to scan for NICs..\n");
}

initiateNetworking() không chạm phần cứng: nó chỉ đặt selectedNIC = 0. Thứ tự vẫn quan trọng. Trong lúc initiatePCI() quét bus, driver gọi createNewNIC(), và hàm này mới là chỗ gán selectedNIC. Gọi initiateNetworking() sau PCI thì nó xoá NIC vừa tìm thấy về 0. Cả hai cũng phải sau initiateTasks() và initiateKernelThreads(), vì lwIP tạo thread riêng và frame nhận được xử lý trong thread helper.

2. struct NIC: một card, bọc quanh một netif của lwIP

c
// include/nic_controller.h
typedef enum NIC_TYPE { NE2000, RTL8139, RTL8169, E1000 } NIC_TYPE;

struct NIC {
  struct netif lwip;     // lwIP's view of this card

  NIC_TYPE type;
  uint16_t mtu;
  uint8_t  mintu;
  void    *infoLocation; // driver-private state (E1000_interface for e1000)
  uint8_t  MAC[6];
  uint8_t  ip[4];
  uint8_t  serverIp[4];
  uint8_t  dnsIp[4];
  uint8_t  subnetMask[4];
  uint8_t  irq;

  arpStore arp;
  UdpStore udp;
};

NIC *selectedNIC;
  • lwip đứng đầu struct: con trỏ tới netif mà lwIP đưa lại cho cavOS cũng là con trỏ tới NIC.
  • type chọn hàm gửi; infoLocation giữ trạng thái riêng của driver (Bài 14).
  • ip, arp, udp là của một stack tự viết cũ trong networking/stack/ (arp.c, ipv4.c, udp.c...). Các file đó vẫn được build, nhưng không còn chỗ nào ngoài thư mục đó gọi tới: mọi frame giờ đi qua lwIP.
  • Chỉ có một selectedNIC: card tìm thấy sau cùng thắng.

3. initiateNIC(): thử từng driver, rồi dựng lwIP

c
void initiateNIC(PCIdevice *device) {
  if (initiateNe2000(device) || initiateRTL8139(device) ||
      initiateRTL8169(device) || initiateE1000(device)) {
    // selectedNIC = newly created NIC structure
    tcpip_init(lwipInitInThread, selectedNIC);
  }
}

// returns UNINITIALIZED!! NIC struct
NIC *createNewNIC(PCI *pci) {
  NIC *nic = malloc(sizeof(NIC));
  memset(nic, 0, sizeof(NIC));
  nic->mtu = 1500;
  pci->extra = nic;
  selectedNIC = nic;
  return nic;
}

initiatePCI() gọi initiateNIC() cho mọi thiết bị class 0x02 (mạng). Mỗi initiateXxx tự kiểm vendor/device ID, không phải thì trả false. Driver nào nhận card thì gọi createNewNIC() và điền MAC, ring, IRQ. Sau đó tcpip_init() của lwIP tạo thread tcpip (qua sys_thread_new, xem mục 7) và hẹn chạy lwipInitInThread trong thread đó.

4. lwipInitInThread(): gắn card vào lwIP và xin IP

c
void lwipInitInThread(void *nicPre) {
  NIC *nic = (NIC *)nicPre;
  struct ip4_addr netmask;
  struct netif *this_netif = &nic->lwip;
  ...
  IP4_ADDR(&netmask, 255, 255, 255, 0);
  netif_add(this_netif, NULL, &netmask, NULL, NULL, lwipDummyInit,
            tcpip_input); // ethernetif_init_low

  this_netif->output = etharp_output;
  this_netif->linkoutput = lwipOutput;
  netif_set_default(this_netif);
  this_netif->hwaddr_len = ETHARP_HWADDR_LEN;
  this_netif->hwaddr[0] = nic->MAC[0]; // or whatever u like
  ...
  this_netif->mtu = nic->mtu;
  this_netif->flags = NETIF_FLAG_BROADCAST | NETIF_FLAG_ETHARP |
                      NETIF_FLAG_ETHERNET | NETIF_FLAG_LINK_UP;
  netif_set_up(this_netif);
  err_t out = dhcp_start(this_netif);
  ...
}
  • netif_add(..., tcpip_input): frame nhận được đưa vào lwIP bằng tcpip_input, hàm này gửi frame sang thread tcpip qua mailbox. Không gọi thẳng giao thức từ thread khác.
  • output = etharp_output: gửi gói IP thì lwIP tự tra bảng ARP (hỏi ARP nếu chưa có MAC) rồi ghép header Ethernet.
  • linkoutput = lwipOutput: chỗ lwIP giao một frame hoàn chỉnh cho cavOS (mục 5).
  • dhcp_start: bắt đầu DHCP; từ đây lwIP tự gửi DISCOVER, chờ OFFER, gửi REQUEST, chờ ACK, rồi tự đặt IP, mask, router cho netif.

5. Đường gửi: lwIP → lwipOutput → driver

c
err_t lwipOutput(struct netif *netif, struct pbuf *p) {
  uint8_t     *complete = malloc(p->tot_len);
  struct pbuf *browse = p;
  uint32_t     cnt = 0;

  while (browse) {
    memcpy(&complete[cnt], browse->payload, browse->len);
    cnt += browse->len;
    browse = browse->next;
  }
  ...
  PCI *pci = LinkedListSearch(&dsPCI, lwipOutputCb, netif);
  NIC *nic = (NIC *)pci->extra;
  sendPacketRaw(nic, complete, p->tot_len);
  free(complete);
  return ERR_OK;
}

lwIP giữ một gói thành chuỗi pbuf (header ở một mảnh, dữ liệu ở mảnh khác) để khỏi chép khi thêm header. Card ở đây nhận một buffer liền, nên cavOS gom chuỗi lại vào một vùng malloc, tìm NIC của netif trong danh sách PCI, rồi sendPacketRaw chọn hàm gửi theo nic->type (sendE1000...). Hàm gửi của E1000 chờ card báo xong (Bài 14), nên khi lwipOutput trả về thì frame đã lên dây và complete trả lại được.

6. Đường nhận: ngắt → netQueue → thread helper → lwIP

c
// include/nic_controller.h
#define PACKET_MAX 1600
#define QUEUE_MAX 128
typedef struct QueuePacket {
  bool exists;
  NIC *nic;
  uint8_t  buff[PACKET_MAX];
  uint16_t packetLength;
} QueuePacket;

// drivers/nics/nic_controller.c -- called by the card's IRQ handler
void netQueueAdd(NIC *nic, uint8_t *packet, uint16_t packetLength) {
  if ((netQueueWrite + 1) % QUEUE_MAX == netQueueRead) {
    debugf("[netqueue] New %d length packet dropped!\n", packetLength);
    return;
  }
  QueuePacket *item = &netQueue[netQueueWrite];
  item->nic = nic;
  memcpy(item->buff, packet, packetLength);
  item->packetLength = packetLength;
  netQueueWrite = (netQueueWrite + 1) % QUEUE_MAX;
}

// entry/kernel_helper.c -- runs in the helper thread
void helperNet() {
  while (true) {
    if (netQueueRead == netQueueWrite)
      return;
    handlePacket(netQueue[netQueueRead].nic, netQueue[netQueueRead].buff,
                 netQueue[netQueueRead].packetLength);
    netQueueRead = (netQueueRead + 1) % QUEUE_MAX;
  }
}

void handlePacket(NIC *nic, void *packet, uint32_t size) {
  struct pbuf *p = pbuf_alloc(PBUF_RAW, size, PBUF_RAM);
  uint8_t     *targ = (uint8_t *)p->payload;
  for (int i = 0; i < size; i++)
    targ[i] = ((uint8_t *)packet)[i];
  nic->lwip.input(p, &nic->lwip);
}
  • Hàng đợi vòng 128 ô, mỗi ô 1600 byte (đủ một frame Ethernet 1514 byte). Một người ghi (handler ngắt), một người đọc (thread helper): chỉ người ghi dời netQueueWrite, chỉ người đọc dời netQueueRead, nên không cần khoá. Hàng đầy thì frame mới bị bỏ.
  • Vì sao không gọi lwIP ngay trong ngắt: handler chạy với IF tắt, không được chờ khoá hay cấp bộ nhớ lâu. lwIP thì cần cả hai. Nên handler chỉ chép, việc nặng để thread helper làm sau.
  • Thread helper (kernelHelpEntry, Bài 12) lặp: helperNet, helperReaper, helperVolatilePoll, handControl. Frame vì vậy được xử lý ở lần helper chạy kế tiếp, cỡ vài ms sau ngắt.
  • nic->lwip.input là tcpip_input (mục 4): frame lại được gửi tiếp sang thread tcpip, nơi lwIP đọc Ethernet → ARP hoặc IP → UDP/TCP.

7. sys_arch.c: lwIP chạy trên task của cavOS

c
// networking/lwip/sys_arch.c
sys_thread_t sys_thread_new(const char *pcName,
                            void (*pxThread)(void *pvParameters), void *pvArg,
                            int iStackSize, int iPriority) {
  Task *task = taskCreateKernel((uint64_t)pxThread, (uint64_t)pvArg);
  taskNameKernel(task, lwipCmdline, sizeof(lwipCmdline));
  return task->id;
}

uint32_t sys_arch_sem_wait(sys_sem_t *sem, uint32_t timeout) {
  if (timeout) {
    debugf("[lwip::glue] todo: Timeout\n");
    panic();
  }
  bool ret = semaphoreWait(sem, timeout);
  return ret ? 0 : SYS_ARCH_TIMEOUT;
}

uint32_t sys_now(void) { return timerBootUnix * 1000 + timerTicks; }

lwIP không biết gì về hệ điều hành bên dưới; nó gọi một bộ hàm sys_* mà mỗi OS tự viết. Ở cavOS: thread = taskCreateKernel (Bài 12), semaphore và mailbox chờ bằng handControl(), đồng hồ = giờ lúc boot cộng tick 1 ms. lwipopts.h chọn LWIP_DHCP 1 và mailbox 32 ô (TCPIP_MBOX_SIZE).

8. Phía userspace: socket là một file

c
// networking/socket.c
size_t socketRecv(OpenFile *fd, uint8_t *in, size_t limit, int flags) {
  UserSocket *userSocket = (UserSocket *)fd->dir;
  int lwipOut = -1;
  while (true) {
    if (!(fd->handlers->internalPoll(fd, EPOLLIN) & EPOLLIN)) {
      if (fd->flags & O_NONBLOCK || flags & MSG_DONTWAIT) { lwipOut = -1; errno = EAGAIN; break; }
      if (signalsPendingQuick(currentTask)) { lwipOut = -1; errno = EINTR; break; }
      continue;
    }
    lwipOut = lwip_recv(userSocket->lwipFd, in, limit, flags);
    if (lwipOut >= 0 || errno != EAGAIN)
      break;
  }
  ...
}

Chương trình ring 3 gọi socket(), connect(), recv() như trên Linux. Syscall (Bài 16) tạo một OpenFile mà handler trỏ vào socket.c, và socket.c gọi API socket của lwIP (lwip_send, lwip_recv...). Chờ dữ liệu bằng vòng hỏi lại internalPoll, thoát khi có tín hiệu (EINTR). Phần userspace là Bài 18.

Đọc DISCOVER từng lớp:

  • Ethernet (14 byte): đích ff:ff:ff:ff:ff:ff (broadcast, chưa biết ai cấp IP), nguồn 52:54:00:12:34:56 (MAC của card), ethertype 08 00 = IPv4.
  • IPv4 (20 byte): 45 = version 4, header 5 từ 32 bit; tổng dài 01 48 = 328; TTL 40 = 64; giao thức 11 = 17 = UDP; checksum 79 a5; nguồn 0.0.0.0 (chưa có IP), đích 255.255.255.255. Mọi số đều big-endian.
  • UDP (8 byte): cổng nguồn 00 44 = 68, đích 00 43 = 67, dài 01 34 = 308.
  • DHCP: 01 = request, 01 06 = Ethernet, MAC dài 6; mã giao dịch 4c 41 42 38 ("LAB8"); cờ 80 00 = xin trả lời bằng broadcast; MAC lặp lại ở chaddr. Sau 236 byte cố định là "magic cookie" 63 82 53 63 rồi các option: 35 01 01 = loại tin 1 (DISCOVER), 37 03 01 03 06 = xin mask, router, DNS, ff = hết.
  • ARP reply nhận về: ethertype 08 06; 00 01 Ethernet, 08 00 IPv4, 06 04 = MAC 6 byte, IP 4 byte; 00 02 = reply; "10.0.2.2 là 52:55:0a:00:02:02". Frame dài 64 byte vì router của QEMU đệm cho đủ cỡ tối thiểu của Ethernet.
  • Frame nhận đi đúng đường cavOS: IRQ ở t=1312, thread helper xử lý ở t=1316.

Lab còn chạy chính cavOS với cùng card và ghi pcap: lwIP gửi DISCOVER/REQUEST giống lab, rồi ba ARP probe "có ai dùng 10.0.2.15 không?" (RFC 5227) trước khi nhận địa chỉ.

Tự kiểm tra

Bốn câu, trả lời bằng đọc code ở trên.

Đổi thứ tự trong _start(): initiatePCI() trước, initiateNetworking() sau. Mạng còn chạy không?

Thread lwIP vẫn được tạo (nó được tạo trong initiatePCI) và nhận con trỏ NIC đúng. Nhưng selectedNIC bị đặt về 0, mà handler ngắt của E1000 đọc selectedNIC->infoLocation: ngắt đầu tiên của card đọc con trỏ NULL và kernel hỏng.

Vì sao netQueue không cần spinlock dù cả ngắt lẫn thread helper đều chạm vào nó?

Chỉ có một bên ghi (handler, dời netQueueWrite) và một bên đọc (helper, dời netQueueRead), trên một CPU. Mỗi bên chỉ sửa chỉ số của mình và đọc chỉ số của bên kia. Hàng đợi một người ghi, một người đọc như vậy đúng mà không cần khoá, miễn là ghi dữ liệu xong mới dời chỉ số.

Trong DISCOVER, IP nguồn là 0.0.0.0 và MAC đích là broadcast. Vì sao?

Máy chưa có IP, nên không có gì để điền nguồn. Nó cũng chưa biết máy chủ DHCP là ai, nên gửi cho mọi máy trong mạng (MAC ff:ff:ff:ff:ff:ff, IP 255.255.255.255).

Đọc trường "tổng dài" của gói IPv4 bằng *(uint16_t *) trên x86 với byte 01 48. Ra số mấy?

0x4801 = 18433, vì x86 đọc byte thấp trước. Phải đảo byte (ntohs) để ra 0x0148 = 328.

Câu hỏi của dàn ý cũ, vài điểm đáng để ý trong phần keo, và chỗ tra trong spec.

Câu hỏi mở (đã trả lời)

  • Thứ tự init: networking trước hay NIC trước? Networking trước (initiateNetworking chỉ đặt selectedNIC = 0), PCI sau. lwIP được dựng bên trong initiatePCI, ngay khi một driver nhận card (tcpip_init).
  • Endianness mạng và host? Mạng big-endian, x86 little-endian. Header Ethernet của sendPacket dùng switch_endian_16; mọi thứ khác do lwIP đảo.
  • Stack tối thiểu Ethernet → ARP → IPv4 → ICMP/UDP? cavOS có hai: stack tự viết cũ trong networking/stack/ (không còn được gọi), và lwIP (đang dùng) có đủ cả TCP, DHCP, DNS.

Vài điểm yếu trong phần keo

  • sys_arch_sem_wait panic nếu lwIP xin chờ có thời hạn (timeout != 0). lwIP hiện không gọi kiểu đó với cấu hình này, nhưng bật thêm tính năng có thể làm kernel dừng.
  • lwipOutput malloc mỗi lần gửi rồi tìm NIC bằng duyệt danh sách PCI; với một card thì không sao, nhưng mỗi frame tốn một lần cấp và trả bộ nhớ.
  • socketRecv chờ bằng vòng continue không nhường CPU: task userspace đang chờ dữ liệu quay cho tới khi bị timer cắt.
  • Kiểm tra MTU trong sendPacketRaw so cả frame (đã có 14 byte header) với mtu = 1500, nên frame 1501–1514 byte (gói IP đủ 1500 byte) bị bỏ.

Ánh xạ spec

  • IEEE 802.3 (Ethernet): header 14 byte, cỡ frame tối thiểu 60 byte + 4 byte CRC, tối đa 1514 + 4.
  • RFC 826 (ARP), RFC 791 (IPv4: header, checksum, TTL), RFC 768 (UDP), RFC 792 (ICMP echo), RFC 2131 + RFC 2132 (DHCP và các option 53, 55, 1, 3, 6, 51), RFC 5227 (ARP probe).
  • lwIP: tài liệu "sys_arch" (các hàm OS phải viết) và tcpip_init/tcpip_input (chế độ có thread, khác chế độ NO_SYS).
