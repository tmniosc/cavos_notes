Bài 15 - AHCI & Filesystems

Status doneTags step, ahci, sata, prdt, mbr, vfs, mount, fat32, ext2, inode

Hàm: initiateAHCI(), ahciPortRebase(), ahciRead() (drivers/ahci.c), openDisk(), getDiskBytes() (drivers/disk.c), fsMount(), fsDetermineMountPoint() (filesystems/vfs/vfs_mnt.c), fsOpenGeneric(), fsRead() (filesystems/vfs/vfs_controller.c), fat32Mount(), ext2Mount() · Phụ thuộc: vòng quét PCI, BAR, bus master, DMA từ Bài 14 - PCI & NIC; VirtualAllocate, VirtualToPhysical từ Bài 6; task và currentTask từ Bài 12.

Mục đích

Đọc được file trên ổ cứng: tìm controller, nói chuyện với ổ đĩa, hiểu cách file được xếp trên đĩa.

Tới đây mọi thứ kernel biết đều do Limine đưa vào RAM. Từ bài này cavOS tự đọc ổ đĩa. Có ba tầng: driver AHCI nói chuyện với controller SATA để đọc/ghi từng sector, filesystem (FAT32, ext2) biết sector nào thuộc file nào, và VFS ghép các filesystem thành một cây thư mục duy nhất. _start() mount ổ hai lần: phân vùng ext2 ở / (hệ thống, có /bin/bash), phân vùng FAT32 ở /boot/ (Limine và kernel). Bài 18 nạp chương trình từ chính cây này.

Nói thật đơn giản

Ổ cứng là một dãy ô 512 byte đánh số 0, 1, 2… (sector). Controller AHCI là người thủ kho: kernel viết phiếu "lấy cho tôi 2 ô bắt đầu từ ô 84800, đặt vào chỗ này trong RAM", bỏ phiếu vào một trong 32 khay (command slot), rồi gõ chuông. Thủ kho tự mang hàng vào RAM (DMA) và gạt khay về "trống" khi xong.

Ô đầu tiên của ổ là mục lục (MBR): ổ chia làm mấy phần, mỗi phần bắt đầu ở ô nào. Mỗi phần có cách xếp đồ riêng. FAT32 giống sổ ghi "cluster này xong thì sang cluster kia". ext2 giống thư viện có thẻ mượn (inode): mỗi file một thẻ ghi cỡ file và các số ô chứa nó; thư mục chỉ là danh sách "tên → số thẻ". VFS là cái bảng chỉ đường: đường dẫn bắt đầu bằng /boot/ thì sang kho FAT32, còn lại thì sang kho ext2.

Cần biết trước

Bốn ý về lưu trữ; BAR, bus master và DMA đã có ở Bài 14.

  • Sector và LBA. Ổ đĩa được đánh địa chỉ theo sector 512 byte, số thứ tự gọi là LBA (Logical Block Address). Lệnh READ DMA EXT của ATA nhận LBA 48 bit và số sector.
  • AHCI. Controller SATA chuẩn (Advanced Host Controller Interface). Thanh ghi nằm trong BAR5 (gọi là ABAR): phần chung, rồi 32 khối 128 byte cho 32 cổng. Mỗi cổng có một command list 32 slot; mỗi slot trỏ tới một command table chứa lệnh ATA (gói 20 byte gọi là FIS) và bảng PRDT (các vùng RAM nhận dữ liệu, bằng địa chỉ vật lý).
  • MBR. Sector 0: 446 byte code, rồi 4 mục phân vùng 16 byte ở offset 0x1BE (loại, LBA đầu, số sector), kết thúc bằng 55 AA.
  • FAT32 và ext2. FAT32 chia vùng dữ liệu thành cluster; bảng FAT ghi cluster kế tiếp của mỗi cluster, thành chuỗi. ext2 chia thành block và nhóm block; mỗi file có một inode giữ cỡ, quyền, và 15 số block (12 trực tiếp, 1 gián tiếp 1 cấp, 1 gián tiếp 2 cấp, 1 gián tiếp 3 cấp).
  • Đã gặp: BAR, command register, DMA, vòng descriptor ở Bài 14; VA → PA ở Bài 6; mount /dev/ cho bàn phím ở Bài 11.

1. Vị trí trong _start()

2. initiateAHCI(): nhận controller

c
bool initiateAHCI(PCIdevice *device) {
  const AHCI_DEVICE *ahciDevice = isAHCIcontroller(device);   // table of vendor:device ids
  if (!ahciDevice)
    return false;
  ...
  uint32_t base = details->bar[5] & 0xFFFFFFF0;              // ABAR
  // Enable PCI Bus Mastering, memory access and interrupts (if not already)
  ...
  HBA_MEM *mem = (HBA_MEM *)(bootloader.hhdmOffset + base); //!
  ...
  // do a full HBA reset (as per 10.4.3)
  mem->ghc |= (1 << 0);
  while (mem->ghc & (1 << 0))
    ;

  if (!(mem->bohc & 2) || mem->cap2 & AHCI_BIOS_OWNED) {
    debugf("[pci::ahci] Performing BIOS->OS handoff required!\n");
    mem->bohc = (mem->bohc & ~8) | 2;
    while ((mem->bohc & 1))
      ;
    ...
  }

  if (!(mem->ghc & (1 << 31)))
    mem->ghc |= (1 << 31);                                    // AE: AHCI mode

  ahciPortProbe(ahciPtr, mem);

  // enable interrupts
  uint8_t targIrq = ioApicPciRegister(device, details);
  pci->irqHandler = registerIRQhandler(targIrq, &ahciInterruptHandler);
  if (!(mem->ghc & (1 << 1)))
    mem->ghc |= 1 << 1;
  return true;
}
  • Bật bus master và memory space y như card mạng ở Bài 14: controller cần tự ghi vào RAM.
  • GHC.HR (bit 0) reset cả controller; nó tự xoá bit khi xong. Sau reset mọi cổng về trạng thái ban đầu.
  • BOHC: nếu firmware đang dùng controller, OS xin quyền (bit OOS) và chờ firmware nhả (bit BOS về 0).
  • GHC.AE (bit 31): chạy ở chế độ AHCI thay vì chế độ IDE cũ. GHC.IE (bit 1) bật ngắt cho cả controller.

3. Dò cổng và "rebase": chuẩn bị bộ nhớ cho mỗi cổng

c
int ahciPortType(HBA_PORT *port) {
  uint32_t ssts = port->ssts;
  uint8_t ipm = (ssts >> 8) & 0x0F;
  uint8_t det = ssts & 0x0F;
  if (det != HBA_PORT_DET_PRESENT) return AHCI_DEV_NULL;   // 3: device present, link up
  if (ipm != HBA_PORT_IPM_ACTIVE)  return AHCI_DEV_NULL;   // 1: active
  switch (port->sig) {
  case SATA_SIG_ATAPI: return AHCI_DEV_SATAPI;
  case SATA_SIG_SEMB:  return AHCI_DEV_SEMB;
  case SATA_SIG_PM:    return AHCI_DEV_PM;
  default:             return AHCI_DEV_SATA;
  }
}

void ahciPortRebase(ahci *ahciPtr, HBA_PORT *port, int portno) {
  ahciCmdStop(port); // Stop command engine
  port->ie = 1;
  // Command list: 1K-byte aligned, 32 commands, 32 bytes each = 1K per port
  void  *clbVirt = VirtualAllocate(clbPages);
  size_t clbPhys = VirtualToPhysical((size_t)clbVirt);
  port->clb = SPLIT_64_LOWER(clbPhys);
  port->clbu = SPLIT_64_HIGHER(clbPhys);
  // FIS: 256-byte aligned, 32 commands, 256 bytes each = 8K per port
  ...
  port->fb = SPLIT_64_LOWER(fbPhys);
  // Command table: 128-byte aligned, 32 commands, AHCI_MEM_TABLE * 32
  for (int i = 0; i < 32; i++) {
    cmdheader[i].prdtl = AHCI_PRDTS;
    size_t ctbaPhysCurr = ctbaPhys + i * AHCI_MEM_TABLE;
    cmdheader[i].ctba = SPLIT_64_LOWER(ctbaPhysCurr);
    cmdheader[i].ctbau = SPLIT_64_HIGHER(ctbaPhysCurr);
  }
  ...
  ahciCmdStart(port); // Start command engine: FRE then ST
  ahciPtr->sata |= (1 << portno);
}
  • SSTS: DET = 3 nghĩa là có thiết bị và đường SATA đã nối; IPM = 1 là đang hoạt động. SIG là chữ ký thiết bị gửi lên: 0x00000101 ổ ATA, 0xEB140101 ổ ATAPI (CD).
  • Mỗi cổng cần 3 vùng nhớ cho HBA dùng: command list (32 header × 32 byte), vùng nhận FIS (thiết bị báo trạng thái về đây), và 32 command table. Cả ba đưa cho HBA bằng địa chỉ vật lý.
  • Engine phải dừng (ST = 0, chờ CR = 0) trước khi đổi CLB/FB, rồi bật lại: FRE (nhận FIS) trước, ST (chạy lệnh) sau.

4. ahciRead(): một lệnh đọc

c
bool ahciRead(ahci *ahciPtr, uint32_t portId, HBA_PORT *port, uint32_t startl,
              uint32_t starth, uint32_t count, uint8_t *buff) {
  port->is = (uint32_t)-1; // Clear pending interrupt bits
  int slot = ahciCmdFind(ahciPtr, port);                    // a slot not set in SACT | CI
  HBA_CMD_TBL *cmdtbl =
      ahciSetUpCmd(ahciPtr, portId, slot, (uint16_t *)buff, count, false);
  FIS_REG_H2D *cmdfis = (FIS_REG_H2D *)(&cmdtbl->cfis);
  cmdfis->fis_type = FIS_TYPE_REG_H2D;
  cmdfis->c = 1; // Command
  cmdfis->command = ATA_CMD_READ_DMA_EX;
  cmdfis->lba0 = (uint8_t)startl;
  ...
  cmdfis->device = 1 << 6; // LBA mode
  cmdfis->countl = count & 0xFF;
  cmdfis->counth = (count >> 8) & 0xFF;
  if (!ahciPortReady(port))                                 // wait while TFD has BSY or DRQ
    return false;
  return ahciCmdIssue(ahciPtr, port, slot);                 // CI = 1 << slot, spin until it clears
}

// inside ahciSetUpCmd: the PRDT
    size_t targPhys = VirtualToPhysical((size_t)buff);
    cmdtbl->prdt_entry[i].dba = SPLIT_64_LOWER(targPhys);
    cmdtbl->prdt_entry[i].dbc = spaceCovered - 1; // up to 4 MiB
    cmdtbl->prdt_entry[i].i = 1;

Driver chờ bằng cách đọc CI liên tục cho tới khi bit của slot về 0; handler ngắt AHCI chỉ xoá các bit trạng thái (và panic nếu có lỗi task file). Mỗi entry PRDT mô tả một vùng RAM liền về vật lý, tối đa 4 MiB; với 8 entry một lệnh đọc được tối đa 32 MiB.

5. drivers/disk.c: MBR và "ổ số 0"

c
bool openDisk(uint32_t disk, uint8_t partition, mbr_partition *out) {
  uint8_t *rawArr = (uint8_t *)malloc(SECTOR_SIZE);
  getDiskBytes(rawArr, 0x0, 1);
  bool ret = validateMbr(rawArr);                // bytes 510, 511 == 0x55, 0xAA
  if (!ret)
    return false;
  memcpy(out, (void *)((size_t)rawArr + mbr_partition_indexes[partition]),
         sizeof(mbr_partition));                  // 0x1BE + 16 * partition
  free(rawArr);
  return true;
}

void diskBytes(uint8_t *target_address, uint32_t LBA, uint32_t sector_count,
               bool write) {
  PCI *browse = LinkedListSearch(&dsPCI, diskBytesCb, 0);   // first AHCI controller with a disk
  ...
  ahci *target = (ahci *)browse->extra;
  int   pos = 0;
  while (!(target->sata & (1 << pos)))
    pos++;                                                  // first SATA port
  (write ? ahciWrite : ahciRead)(target, pos, &target->mem->ports[pos], LBA, 0,
                                 sector_count, target_address);
}

Tham số disk của openDisk không được dùng: mọi lần đọc đi tới cổng SATA đầu tiên của controller AHCI đầu tiên. diskBytesMax cắt yêu cầu lớn thành các lệnh vừa với 8 PRDT.

c
bool isFat(mbr_partition *mbr) {
  uint8_t *rawArr = (uint8_t *)malloc(SECTOR_SIZE);
  getDiskBytes(rawArr, mbr->lba_first_sector, 1);
  bool ret = (rawArr[66] == 0x28 || rawArr[66] == 0x29);   // FAT32 extended boot signature
  free(rawArr);
  return ret;
}

bool isExt2(mbr_partition *mbr) { return mbr->type == 0x83; }

MountPoint *fsMount(char *prefix, CONNECTOR connector, uint32_t disk,
                    uint8_t partition) {
  MountPoint *mount = LinkedListAllocate(&dsMountPoint, sizeof(MountPoint));
  ...
  switch (connector) {
  case CONNECTOR_AHCI:
    if (!openDisk(disk, partition, &mount->mbr)) { fsUnmount(mount); return 0; }
    if (isFat(&mount->mbr)) {
      mount->filesystem = FS_FATFS;
      ret = fat32Mount(mount);
    } else if (isExt2(&mount->mbr)) {
      mount->filesystem = FS_EXT2;
      ret = ext2Mount(mount);
    }
    break;
  case CONNECTOR_DEV:  ... devMount(mount);  break;
  case CONNECTOR_SYS:  ... sysMount(mount);  break;
  case CONNECTOR_PROC: ... procMount(mount); break;
  }
  ...
  if (!systemDiskInit && strlength(prefix) == 1 && prefix[0] == '/')
    systemDiskInit = true;
  return mount;
}

void fsDetermineMountPointCb(void *data, void *ctx) {
  MountPoint       *browse = data;
  MountPointCbArgs *p = ctx;
  size_t len = strlength(browse->prefix) - 1; // without trailing /
  if (len >= p->largestLen && memcmp(p->filename, browse->prefix, len) == 0 &&
      (p->filename[len] == '/' || p->filename[len] == '\0')) {
    p->largestAddr = browse;
    p->largestLen = len;
  }
}
  • FAT32 được nhận bằng nội dung (byte 66 của boot sector), ext2 chỉ bằng loại phân vùng trong MBR. Trong disk.img của cavOS cả hai phân vùng đều mang loại 0x83, và phân vùng đầu vẫn được nhận là FAT32 vì isFat được thử trước.
  • Mỗi filesystem gắn bảng hàm của nó (mount->handlers: open, read, write, seek, stat...) vào mount point.
  • Tìm mount point = prefix dài nhất khớp với đầu đường dẫn, và ký tự kế tiếp phải là / hoặc hết chuỗi: /boot/kernel.bin thuộc /boot/, /bootstrap.txt thuộc /.

  • Superblock luôn nằm ở byte 1024 của phân vùng; chữ ký 0xEF53. cavOS chỉ nhận ext2 có đúng một tính năng bắt buộc là FILETYPE (mục thư mục có byte kiểu).

8. FAT32: boot sector và chuỗi cluster

c
bool fat32Mount(MountPoint *mount) {
  ...
  fat->offsetBase = mount->mbr.lba_first_sector; // 2048 (in LBA)
  getDiskBytes(firstSec, fat->offsetBase, 1);
  memcpy(&fat->bootsec, firstSec, sizeof(FAT32BootSector));
  fat->offsetFats = fat->offsetBase + fat->bootsec.reserved_sector_count;
  fat->offsetClusters =
      fat->offsetFats +
      fat->bootsec.table_count * fat->bootsec.extended_section.table_size_32;
  ...
}

uint32_t fat32FATtraverse(FAT32 *fat, uint32_t offset) {
  uint32_t offsetFAT = offset * 4; // every entry is sizeof(uint32_t) = 4
  uint32_t offsetSector = fat->offsetFats + (offsetFAT / bytesPerCluster);
  uint32_t offsetEntry = offsetFAT % bytesPerCluster;
  fat32FATfetch(fat, offsetSector, bytes);          // with a small cache of FAT sectors
  uint32_t ret = (*retLocation) & 0x0FFFFFFF; // remember; we're on FAT32
  if (ret >= 0x0FFFFFF8) return 0;                  // end of cluster chain
  if (ret == 0x0FFFFFF7) return 0;                  // bad cluster
  return ret;
}

Vùng dữ liệu bắt đầu sau các sector dự trữ và các bảng FAT; cluster đầu tiên mang số 2. Ô thứ c của bảng FAT là số cluster kế tiếp của file, nên đọc một file là đi theo chuỗi cluster. Mục thư mục FAT chứa luôn cỡ file và cluster đầu, không có inode. FAT không có quyền file hay symlink: lstat của nó trỏ về fat32Stat.

Tự kiểm tra

Năm câu; có câu cần tính.

Phân vùng ext2 bắt đầu ở LBA 81920, block 1 KiB. Block 1440 nằm ở LBA nào?

81920 + 1440 × 1024 / 512 = 84800. Đó là sector chứa /etc/motd trong lab.

Inode 20, mỗi nhóm 2048 inode, inode 256 byte. Nó nằm ở nhóm nào và byte thứ mấy trong bảng inode của nhóm?

Nhóm (20 - 1) / 2048 = 0, chỉ số (20 - 1) % 2048 = 19, nên ở byte 19 × 256 = 4864 tính từ đầu bảng inode của nhóm 0.

Vì sao driver phải dừng engine của cổng (ST = 0, chờ CR = 0) trước khi ghi CLB?

Khi engine chạy, HBA có thể đang đọc command list cũ. Đổi địa chỉ giữa chừng làm nó đọc nửa cũ nửa mới. Đặc tả AHCI chỉ cho đổi CLB/FB khi CR và FR đều bằng 0.

fsMount("/boot/", ...) và fsMount("/", ...): đổi thứ tự hai lời gọi thì /boot/kernel.bin có còn tìm đúng không?

Vẫn đúng. fsDetermineMountPoint duyệt mọi mount point và chọn prefix dài nhất khớp, không phụ thuộc thứ tự mount.

Một file FAT32 dài 381 cluster. Không có cache, đọc cả file cần bao nhiêu lần đọc bảng FAT?

381: mỗi cluster tra một lần để biết cluster kế tiếp (lần cuối ra "hết chuỗi"). Lab không cache nên tốn 763 lệnh AHCI; cavOS giữ vài sector FAT gần nhất trong cache.

Đọc thêm

Câu hỏi của dàn ý cũ, những chỗ driver và filesystem của cavOS lệch khỏi đặc tả, và chỗ tra trong spec.

Câu hỏi mở (đã trả lời)

  • cavOS đọc đĩa bằng gì? Chỉ AHCI (SATA). Không có driver IDE cũ, NVMe hay virtio-blk. make qemu của cavOS gắn ổ bằng -device ahci -device ide-hd.
  • Filesystem nào? ext2 (đọc và ghi) cho /, FAT32 cho /boot/; cộng ba filesystem ảo /dev/, /sys/, /proc/.
  • MBR hay GPT? Chỉ MBR, 4 phân vùng chính; không đọc GPT.

Chỗ lệch khỏi đặc tả

  • Phân loại cổng quá sớm. ahciPortType đọc SIG ngay sau reset HBA, khi chưa bật FRE, nên SIG còn là 0xFFFFFFFF và mọi thiết bị rơi vào nhánh default = "SATA". Lab 0x09 đo được: ổ CD của QEMU bị cavOS coi là đĩa. Vì diskBytes chỉ dùng cổng SATA đầu tiên, máy có ổ CD ở cổng thấp hơn ổ cứng sẽ đọc nhầm sang ổ CD.
  • PRDT giả định buffer liền về vật lý. ahciSetUpCmd tính một giá trị căn trang rồi ghi đè ngay bằng MIN(totalBytes, AHCI_BYTES_PER_PRDT), và lấy PA của trang đầu cho cả entry. Buffer qua VirtualAllocate liền về VA nhưng không chắc liền về PA; khi đó controller ghi vào frame của người khác.
  • Handoff luôn chạy. Điều kiện !(mem->bohc & 2) || ... đúng ngay khi OS chưa đặt OOS, nên dòng "Performing BIOS->OS handoff required!" luôn được in (có trong lab/outputs/cavos-net-run.txt), kể cả trên controller không có cơ chế handoff (CAP2.BOH = 0).
  • Giới hạn block gián tiếp 2 cấp sai đơn vị. baseDoubly = baseSingly + blockSize * itemsPerBlock; đúng phải là itemsPerBlock * itemsPerBlock (số block, không phải số byte). Với block 1 KiB, file vượt 65804 block (≈ 64 MiB) sẽ được tra như gián tiếp 2 cấp với chỉ số vượt khỏi block danh sách thay vì đi sang nhánh 3 cấp.
  • Chờ lệnh xong (ahciCmdIssue) bằng vòng lặp không giới hạn thời gian; handler ngắt panic() khi gặp lỗi task file.
