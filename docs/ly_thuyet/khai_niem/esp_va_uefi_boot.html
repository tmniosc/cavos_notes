ESP và UEFI boot

Tags concept, boot, uefi, disk

Firmware UEFI không biết kernel là gì. Nó chỉ biết chạy một file .efi nằm trên một phân vùng FAT: hoặc file được ghi sẵn trong biến NVRAM Boot####, hoặc file ở đường dẫn dự phòng \EFI\BOOT\BOOTX64.EFI. File đó thường là một bootloader (GRUB, systemd-boot, Limine...) hoặc chính kernel nếu nó là ứng dụng UEFI. Bố cục một ảnh đĩa boot được: Cấu trúc os.img; phần bootloader giao cho kernel: Boot Protocol & Limine.

GPT và EFI System Partition

ESP là "ngăn kéo dành riêng cho firmware": một phân vùng FAT có đánh dấu đặc biệt để firmware biết chỗ tìm bootloader.

  • GPT (GUID Partition Table) là bảng phân vùng chuẩn của UEFI. Header nằm ở LBA 1 với chữ ký EFI PART, có bản sao ở cuối đĩa. Mỗi phân vùng có một type GUID (loại) và một GUID riêng. Sector 0 vẫn chứa một MBR "bảo vệ" (protective MBR, type 0xEE) để công cụ cũ không ghi đè.
  • ESP (EFI System Partition) là phân vùng có type GUID C12A7328-F81F-11D2-BA4B-00A0C93EC93B, định dạng FAT (thường FAT32). Trên đĩa MBR, spec gọi ESP là phân vùng có OS type 0xEF.
  • Firmware có sẵn driver FAT, nên nó đọc được file trên ESP mà không cần hệ điều hành nào.

BootOrder, Boot#### và đường dẫn dự phòng

Firmware có một danh sách "thử boot cái gì trước" lưu trong NVRAM; nếu mục trong danh sách chỉ trỏ tới cả ổ đĩa thì nó tự đi tìm file theo tên quy ước.

  • Boot#### (#### là 4 chữ số hex) là một biến UEFI chứa một EFI_LOAD_OPTION: cờ thuộc tính, tên hiển thị, và một device path (đường dẫn thiết bị: PCI → SATA → phân vùng → file).
  • BootOrder là mảng số 16-bit, liệt kê thứ tự thử các Boot####.
  • Khi device path chỉ tới thiết bị chứ không tới file (đĩa rời, đĩa mới cắm), boot manager tìm \EFI\BOOT\BOOT{arch}.EFI trên phân vùng FAT của thiết bị đó. Với x86-64 là BOOTX64.EFI. Đây là removable media boot path, thường gọi là fallback path.

Cài OS thật thì installer gọi SetVariable để thêm một Boot#### trỏ thẳng tới file của nó (ví dụ \EFI\ubuntu\shimx64.efi). Một OS chưa có installer (hobby kernel, ảnh đĩa chạy thử, USB live) dựa hoàn toàn vào fallback path: chỉ cần đặt bootloader đúng tên ở \EFI\BOOT\.

Ví dụ kho biến của OVMF sau khi boot một ổ SATA không có Boot#### riêng:

text
Boot0000   attr=0x109 "BootManagerMenuApp"            devpath[04/07 04/06]
Boot0001   attr=0x101 "EFI Firmware Setup"            devpath[04/07 04/06]
Boot0002   attr=0x1   "UEFI QEMU HARDDISK QM00013 "   devpath[02/01 01/01 03/12]
Boot0003   attr=0x101 "EFI Internal Shell"            devpath[04/07 04/06]
BootOrder  -> Boot0000,Boot0001,Boot0002,Boot0003
  • OVMF tự tạo Boot0002 cho ổ SATA. Device path chỉ có ACPI (02/01) → PCI (01/01) → SATA (03/12), không có node file, nên boot manager dùng fallback path.
  • Các mục có bit 0x100 (category app) không được boot tự động; bit 0x8 là hidden.

ESP không đúng chuẩn vẫn có thể boot

Spec đòi type GUID (hoặc type 0xEF trên MBR), nhưng nhiều firmware chỉ cần thấy một phân vùng FAT.

Driver FAT của OVMF gắn vào mọi phân vùng FAT, không xét type. Nên một ảnh đĩa MBR với phân vùng FAT32 type 0x83 (Linux) vẫn boot được trong QEMU, dù theo spec nó không phải ESP. Firmware máy thật có thể khắt khe hơn. Muốn chắc: dùng GPT với type GUID của ESP, hoặc MBR với type 0xEF.

Một bootloader đọc kernel thế nào (ví dụ Limine)

Limine là một ứng dụng UEFI, nhưng nó không nhờ firmware đọc file. Nó chỉ mượn firmware để đọc từng sector, còn FAT thì tự hiểu.

  1. Firmware nạp BOOTX64.EFI (một file PE32+, xem PE, ELF và quy ước gọi hàm) vào RAM và gọi điểm vào với hai đối số: ImageHandle và con trỏ EFI_SYSTEM_TABLE.
  2. Limine liệt kê mọi handle có EFI_BLOCK_IO_PROTOCOL (gBS->LocateHandle(ByProtocol, ...) trong common/drivers/disk.s2.c) và đọc sector bằng ReadBlocks. Nó tự đọc bảng MBR/GPT và tự hiểu FAT (common/fs/fat32.s2.c). Trong mã nguồn 10.8.5 không có chỗ nào dùng EFI_SIMPLE_FILE_SYSTEM_PROTOCOL.
  3. Limine tìm file cấu hình trên từng phân vùng theo thứ tự trong common/lib/config.c (init_config_disk, không phân biệt hoa thường): (chỉ bản UEFI) limine.conf nằm cùng thư mục với chính file EFI (ở đây là /EFI/BOOT/limine.conf), rồi /boot/limine/limine.conf, /boot/limine.conf, /limine/limine.conf, /limine.conf.
  4. Limine đọc kernel.bin theo kernel_path, nạp các segment ELF, dựng page table, lấy memory map lần cuối, gọi ExitBootServices (efi_exit_boot_services() trong common/lib/misc.c), rồi nhảy vào điểm vào của kernel.

Vì Limine tự làm phần đọc file, cùng một mã FAT chạy cho cả đường BIOS (đọc sector bằng int 13h) lẫn UEFI.
