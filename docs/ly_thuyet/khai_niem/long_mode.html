Long Mode

Tags concept, cpu, x86-64, boot

Long mode là chế độ 64-bit của CPU x86-64. CPU nào cũng thức dậy ở chế độ 16-bit cũ; muốn chạy kernel 64-bit thì phải có ai đó đưa CPU lên long mode, bật paging, rồi mới nhảy vào kernel. Người đó có thể là bootloader, firmware, hoặc đoạn code đầu tiên của chính kernel.

Các chế độ x86

CPU x86 nào cũng thức dậy ở chế độ 16-bit cũ, rồi phải leo từng nấc lên 64-bit.

Gỡ rối đầy đủ "segment + 3 chế độ": x86 Segmentation.

Vì phải chạy được phần mềm của 40 năm trước, CPU x86-64 vẫn giữ cả ba chế độ. Mỗi chế độ là một "luật chơi" khác nhau cho địa chỉ và thanh ghi:

  • Real mode (16-bit): chế độ lúc bật nguồn. Địa chỉ = segment × 16 + offset, chỉ với tới khoảng 1 MiB. Không có bảo vệ bộ nhớ.
  • Protected mode (32-bit): có GDT, có privilege level (ring 0–3), paging là tuỳ chọn. Với tới 4 GiB.
  • Long mode, Intel gọi là IA-32e mode, có hai chế độ con:
    • 64-bit mode: thanh ghi 64-bit, địa chỉ ảo 64-bit. Kernel 64-bit chạy ở đây.
    • Compatibility mode: vẫn trong long mode (paging 4 cấp vẫn chạy), nhưng code 32-bit cũ chạy được như ở protected mode. Dùng cho chương trình 32-bit trên OS 64-bit.

Chế độ con nào đang chạy do bit L của code segment hiện tại (CS) quyết định: L = 1 là 64-bit mode, L = 0 là compatibility mode. Vì thế mỗi lần nạp CS là một lần có thể đổi chế độ con.

Bit và MSR liên quan

Một nhóm nhỏ bit trong CR0, CR4, EFER và CS quyết định CPU đang ở chế độ nào.

CR0, CR4 là control register, đọc/ghi bằng mov. EFER (Extended Feature Enable Register) là một MSR (model-specific register) số 0xC0000080, đọc/ghi bằng rdmsr/wrmsr.

Leo từ protected mode lên 64-bit

Bốn bước bật bit và một cú nhảy xa, đúng thứ tự trên sơ đồ.

Ví dụ đoạn code đầu tiên của một kernel được nạp ở 32-bit protected mode, paging tắt (như Multiboot làm). Bảng trang pml4 đã dựng sẵn, map ít nhất chính đoạn code này theo kiểu identity (VA = PA), vì ngay sau khi bật PG lệnh kế tiếp vẫn được lấy ở địa chỉ cũ:

asm
bits 32
    mov eax, cr4
    or  eax, 1 << 5            ; CR4.PAE
    mov cr4, eax

    mov eax, pml4              ; physical address of the PML4
    mov cr3, eax

    mov ecx, 0xC0000080        ; EFER
    rdmsr
    or  eax, 1 << 8            ; EFER.LME
    wrmsr

    mov eax, cr0
    or  eax, 1 << 31           ; CR0.PG: now in compatibility mode (LMA = 1)
    mov cr0, eax

    lgdt [gdt64_ptr]           ; a GDT with a code descriptor that has L = 1
    jmp 0x08:long_entry        ; far jump loads CS with L = 1: 64-bit mode

bits 64
long_entry:
    mov ax, 0x10               ; data selector
    mov ds, ax
    mov es, ax
    mov ss, ax
    ; ... set RSP, jump to the higher-half kernel, call the C entry point

Một khi đã ở long mode, kernel không bao giờ tắt PG: tắt nghĩa là rời long mode.

Ai leo thang cho kernel

Mỗi cách boot giao máy cho kernel ở một nấc khác nhau trên thang.

Kể cả khi được giao máy ở 64-bit, kernel vẫn phải tự nạp IDT, GDT và TSS của mình: bootloader thường chỉ hứa những thứ tối thiểu, và để IDT ở trạng thái không xác định. Đọc kỹ phần "machine state at entry" của protocol mình dùng.

Đặc điểm long mode mà kernel nào cũng gặp

Bốn điều của long mode ảnh hưởng thẳng tới code kernel.

  • Địa chỉ ảo canonical 48 bit (hoặc 57 bit) sign-extended: xem Higher-Half Kernel.
  • Paging luôn bật, 4 cấp (PML4) hoặc 5 cấp: xem Paging.
  • Segmentation gần như "phẳng": base/limit bị bỏ qua cho hầu hết segment (trừ FS/GS). GDT vẫn cần, vì CS mang bit L và mức đặc quyền (CPL); TSS vẫn cần cho stack khi đổi ring. Xem GDT.
  • Thanh ghi 64 bit (RAX…R15), quy ước gọi hàm theo System V x86-64 psABI: xem PE, ELF và ABI.

CPU phụ (AP) leo thang thế nào

Mỗi CPU phụ thức dậy ở real mode như lúc bật máy, nên phải leo lại từ đầu.

Máy nhiều nhân có một BSP (bootstrap processor, CPU chạy code boot) và các AP (application processor). Firmware và bootloader chỉ chạy trên BSP. Muốn dùng AP, phải:

  1. Chép một đoạn code nhỏ ("trampoline") xuống dưới 1 MiB, ở đầu một trang (địa chỉ vector × 0x1000).
  2. Gửi IPI INIT rồi SIPI (Startup IPI, mang số vector) tới AP qua Local APIC; thường gửi SIPI hai lần.
  3. AP bắt đầu ở real mode tại địa chỉ đó, chạy trampoline: nạp GDT, bật PE, PAE, nạp CR3, LME, PG, nhảy vào 64-bit, lấy stack riêng, rồi gọi vào kernel.

Hai bẫy hay gặp: trampoline phải chạy được ở địa chỉ thấp trước khi có paging (thường viết bằng asm, tự tính địa chỉ); và GDT của trampoline nằm trên trang chỉ đọc thì phải đặt sẵn bit Accessed, vì CPU tự ghi bit đó khi nạp segment. Một số bootloader làm hộ phần này: Limine đưa mọi AP lên 64-bit rồi cho chúng chờ, tới khi kernel ghi địa chỉ hàm vào trường goto_address.
