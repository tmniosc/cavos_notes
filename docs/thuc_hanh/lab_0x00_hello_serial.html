Lab 0x00 — Hello Serial

Status doneTags lab, hands-on, boot

Tự viết lại phần boot + serial từ số 0 (gộp Bài 1 - Boot & Limine + Bài 2 - Serial UART). Vị trí: ~/oskernel-lab/00-hello-serial/ · source lưu ở lab/src/oskernel-lab/00-hello-serial/.

Mục tiêu

Kernel nhỏ nhất có thể: được Limine nạp, rồi in một dòng ra cổng serial.

  • Limine nạp kernel ELF64 vào Long Mode → nhảy vào entry kmain (= ENTRY(kmain) trong linker.ld).
  • Init COM1 (8N1, 115200) theo UART 16550.
  • In "Hello Serial" ra QEMU serial.

Base revision = 2 (khớp cavOS gốc, không dùng 3) — LIMINE_BASE_REVISION(2) trong kernel.c

  • comment linker.ld. Đã rebuild + boot QEMU lại OK (2026-05-31). Xem Limine Protocol §4.

Các mảnh chính

Bốn file: linker script, request của Limine, driver serial, và kmain.

  • linker.ld: ENTRY(kmain) (lab dùng kmain làm entry, không phải _start), . = 0xffffffff80000000, PHDRS (text/rodata/data = PT_LOAD, không ghi FLAGS → ld tự suy W^X từ section flags — xem Bài 1 - Boot & Limine, "Không ghi FLAGS thì ld tự suy quyền"), . = ALIGN(CONSTANT(MAXPAGESIZE)) giữa các segment (xem Paging ý #3).
  • .limine_requests gói trong KEEP(*(.limine_requests)) (nằm trong :rodata) để Limine quét magic, KEEP chống linker GC bỏ section (chưa ai tham chiếu trực tiếp) — xem Request-Response Mechanism.
  • limine.conf + limine bios-install → đóng gói vào os.img (ảnh đĩa MBR + FAT32 + Limine, dựng bằng scripts/mkimage.sh) — bố cục ảnh đĩa: Cấu trúc os.img.
  • serial.c: outb/inb, init COM1, serial_putc chờ LSR bit5 (THRE).

Kết quả

Một dòng chữ trên serial là bằng chứng cả chuỗi boot chạy đúng.

QEMU -serial stdio in ra Hello Serial.

4 file phân tích build sinh sẵn (soi layout đã học)

Mỗi lần build sinh bốn file để soi kernel đã được xếp ra sao.

Makefile lab tự tạo mỗi lần build — dùng để thấy tận mắt higher-half / ALIGN / W^X:

File Lệnh sinh Cho biết
kernel.map ld -Wl,-Map=kernel.map Layout sau link: section ở địa chỉ nào, kích thước, mốc ALIGN, vị trí symbol
kernel.dis objdump -d -M intel disassembly
kernel.sym nm -n bảng symbol theo địa chỉ
kernel.elf.txt readelf -a toàn bộ ELF: program headers + p_flags (R/X…)

Map file là sản phẩm của LINKER (kernel.bin), KHÔNG phải của kernel.o. .o chưa link nên chưa có địa chỉ cuối để "map". Muốn soi section/flag của riêng .o (trước link): readelf -S kernel.o (→ kernel.o.sections.txt) hoặc objdump -h kernel.o (→ kernel.o.headers.txt)
→ thấy .text=AX, .rodata=A, .data=WA (gốc của W^X, xem Bài 1 - Boot & Limine, "Không ghi FLAGS thì ld tự suy quyền").

Trích kernel.map (bằng chứng cho Paging ý #3):

text
.text    0xffffffff80000000   0xf3            ← kernel ở higher-half
           0xffffffff80000060   kmain          ← entry point
         0xffffffff80001000  . = ALIGN(MAXPAGESIZE)   ← đẩy sang trang mới
.rodata  0xffffffff80001000   0x8a            ← rodata khởi đầu ĐÚNG biên trang 0x1000

Lần chạy 2026-09-03 — cùng kết luận, chỉ khác kích thước:

text
.text           0xffffffff80000000      0x152
                0xffffffff80000000                kmain     ← entry ngay đầu .text
.rodata         0xffffffff80001000       0x4c               ← vẫn đúng biên trang 0x1000
.data           0xffffffff80002000       0x18

readelf -lW kernel.bin xác nhận W^X đúng như Bài 1 - Boot & Limine, "Không ghi FLAGS thì ld tự suy quyền":

text
LOAD 0xffffffff80000000 ... R E     ← .text: đọc + THỰC THI, không ghi
LOAD 0xffffffff80001000 ... R       ← .rodata: chỉ đọc
LOAD 0xffffffff80002000 ... RW      ← .data/.bss: đọc + ghi, không thực thi

Ba segment PT_LOAD rơi đúng 3 trang liền nhau vì linker.ld chèn ALIGN(CONSTANT(MAXPAGESIZE)) và link với -Wl,-z,max-page-size=0x1000 — thiếu cờ này MAXPAGESIZE = 2 MiB, rodata sẽ nhảy lên …80200000 chứ không phải …80001000.
