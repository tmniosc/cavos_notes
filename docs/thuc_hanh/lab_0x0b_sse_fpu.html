Lab 0x0b - SSE & FPU

Status doneTags lab, hands-on, sse, avx, x87, cr0, cr4, xcr0, fxsave, xsave, context switch

Đi cùng bài: Bài 17 - SSE & FPU. Kernel bật x87, SSE và AVX theo đúng initiateSSE() của cavOS, và lưu trạng thái FPU khi đổi task bằng fxsave/fxrstor như schedule() của cavOS. Hai chương trình ring 3 chạy cùng lúc, mỗi cái giữ một mẫu riêng trong YMM0 và trên stack x87, rồi đếm xem sau mỗi lần bị đổi đi và đổi về, mẫu của nó còn nguyên không. Ba bản build so ba cách lưu: fxsave như cavOS, xsave, và không lưu gì.

Vị trí: ~/oskernel-lab/0b-sse-fpu/ (chép từ 0a-fast-syscalls/) · Limine base revision 2. Chạy: make image && make run (QEMU -cpu max). Source ở lab/src/oskernel-lab/0b-sse-fpu/, log đầy đủ ở lab/outputs/lab-0x0b-run.txt.

Chạy

Một bản giống cavOS, hai bản để so.

bash
cd ~/oskernel-lab/0b-sse-fpu
make image && make run                                    # fxsave/fxrstor như cavOS
make clean && make image DEMO=-DXSAVE && make run         # xsave/xrstor
make clean && make image DEMO=-DNO_FPU_SAVE && make run   # không lưu FPU
bash scripts/run_all.sh lab-0x0b-run.txt

Mỗi chương trình fpu: nạp mẫu 32 byte vào YMM0 và một số nguyên vào ST(0), rồi 40 lần: quay khoảng 200000 vòng (đủ để timer 1 ms cắt và đổi sang task kia), cất YMM0 và ST(0) ra stack, so với mẫu. Output thật: QEMU 10.2.1 TCG -cpu max, cross gcc -O2, Limine 8.7.0, chạy ngày 2026-10-03.

Kết quả 1: trước và sau initiateSSE()

Limine để SSE tắt; một lệnh SSE trong ring 3 lúc này là #UD.

text
[kernel] FPU switch mode: fxsave/fxrstor + stmxcsr/ldmxcsr, like cavOS
[sse] left by Limine: CR0 0x80010011 (EM=0 MP=0 TS=0 NE=0), CR4 0x20 (OSFXSR=0 OSXMMEXCPT=0 OSXSAVE=0)

[kernel] task 3 (probe): 18 bytes of code, FPU area at 0xffffffff8001ea40 (FCW 0x37f, MXCSR 0x1f80)
[isr] vector 0x6 #UD Invalid Opcode  err=0x0
      RIP=0x0000008000000000 CS=0x53 RFLAGS=0x10202 RSP=0x0000800000000000 SS=0x4b
      -> fault in ring 3 (CPL 3): kill task 3 (probe), the kernel goes on

[sse] CPUID.1: EDX 0xfcbfbfd (SSE bit25=1 FXSR bit24=1), ECX 0xf6f8320b (XSAVE bit26=1 AVX bit28=1)
[cpu] The xsave instruction is available. Enabling..
[cpu] The AVX extensions are available. Enabling..
[sse] CPUID.0xD: XSAVE area for the bits now in XCR0 = 832 bytes (fxsave: 512)
[sse] after initiateSSE(): CR0 0x80010033 (EM=0 MP=1 TS=0 NE=1), CR4 0x40620 (OSFXSR=1 OSXMMEXCPT=1 OSXSAVE=1), XCR0 0x7

[kernel] task 4 (probe): 18 bytes of code, FPU area at 0xffffffff8001ea40 (FCW 0x37f, MXCSR 0x1f80)
[t=  320] [4 probe  ] exit(0) -> taskKill
  • Trước: CR4.OSFXSR = 0. Lệnh đầu tiên của probe (movaps, tại 0x8000000000) gây #UD.
  • Sau: CR0 thêm MP (bit 1) và NE (bit 5); CR4 thêm OSFXSR (bit 9), OSXMMEXCPT (bit 10), OSXSAVE (bit 18); XCR0 = 7 = x87 + SSE + AVX. Probe chạy được cả movaps lẫn vmovdqu ymm.
  • CPUID.0xD: với 3 thành phần đó, vùng xsave cần 832 byte. fxsave chỉ ghi 512 byte: thiếu đúng 256 byte nửa cao của 16 thanh ghi YMM (16 × 16 byte), cộng phần header.

Kết quả 2: fxsave như cavOS

XMM và x87 sống sót qua đổi task; nửa cao YMM thì không.

text
########## Run 1: make run (fxsave/fxrstor, like cavOS)
[t=  411] [6 fpu_B  ] pattern 0x55: 40 checks after being switched out and back in: XMM0 (low 128 bits) wrong 0, YMM0 high 128 bits wrong 0, x87 ST(0) wrong 0, switched in 32 times
[t=  417] [5 fpu_A  ] pattern 0xaa: 40 checks after being switched out and back in: XMM0 (low 128 bits) wrong 0, YMM0 high 128 bits wrong 40, x87 ST(0) wrong 0, switched in 35 times
  • fpu_A sai nửa cao ở cả 40 lần kiểm. fpu_A nạp YMM0 trước; rồi fpu_B chạy và nạp YMM0 của nó. Khi đổi về A, fxrstor trả lại nửa thấp (XMM0) của A, nhưng nửa cao vẫn là của B, vì fxsave không lưu nó.
  • fpu_B không thấy lỗi chỉ vì nó là task cuối cùng ghi nửa cao, và A không ghi lại nữa. Lỗi thuộc về task bị đè, không phải task đè.
  • x87 ST(0) và XMM0 đúng hết: đó là phần fxsave có lưu.

Kết quả 3: xsave

Cùng chương trình, chỉ đổi lệnh lưu trong scheduler.

text

[kernel] FPU switch mode: xsave/xrstor with mask XCR0 = 7 (DEMO=-DXSAVE)
[t=  434] [6 fpu_B  ] pattern 0x55: 40 checks after being switched out and back in: XMM0 (low 128 bits) wrong 0, YMM0 high 128 bits wrong 0, x87 ST(0) wrong 0, switched in 34 times
[t=  438] [5 fpu_A  ] pattern 0xaa: 40 checks after being switched out and back in: XMM0 (low 128 bits) wrong 0, YMM0 high 128 bits wrong 0, x87 ST(0) wrong 0, switched in 36 times

xsave với mặt nạ EDX:EAX = 7 lưu mọi thành phần đang bật trong XCR0, kể cả nửa cao YMM. Cả hai task đều 0 lỗi. Vùng lưu cần căn 64 byte và đủ cỡ CPUID.0xD báo (832 byte ở đây; lab cấp 1024).

Kết quả 4: không lưu gì

Để thấy vì sao phải lưu.

text
########## Run 3: DEMO=-DNO_FPU_SAVE
[kernel] FPU switch mode: none (DEMO=-DNO_FPU_SAVE)
[t=  423] [5 fpu_A  ] pattern 0xaa: 40 checks after being switched out and back in: XMM0 (low 128 bits) wrong 40, YMM0 high 128 bits wrong 40, x87 ST(0) wrong 40, switched in 32 times
[t=  427] [6 fpu_B  ] pattern 0x55: 40 checks after being switched out and back in: XMM0 (low 128 bits) wrong 0, YMM0 high 128 bits wrong 0, x87 ST(0) wrong 0, switched in 33 times

Không lưu thì A thấy mọi thứ của B: cả YMM0 lẫn số trên đỉnh stack x87 (lệnh fild của B đẩy 2222 lên trên số 1111 của A). Hai task dùng chung một bộ thanh ghi FPU.

Tự kiểm tra

Đoán trước, rồi đổi code và chạy lại.

Đổi chương trình fpu chỉ dùng XMM0 (lệnh movdqu, không dùng YMM). Bản fxsave còn lỗi không?

Không: fxsave lưu đủ XMM0–15. Nhưng nếu task kia vẫn dùng lệnh VEX 128 bit (vmovdqu xmm), lệnh đó xoá nửa cao YMM về 0, nên một task khác đang dùng YMM vẫn mất nửa cao.

Vì sao kernel cavOS (và lab) không cần lưu FPU cho kernel thread?

Kernel biên dịch với -mno-sse -mno-sse2 -mno-80387 -mno-mmx: compiler không bao giờ sinh lệnh FPU/SSE trong code kernel. Thanh ghi FPU lúc đang ở kernel vẫn là của task user vừa chạy, và không ai trong kernel động vào.

Bỏ dòng fninit trong initiateSSE(). Có ảnh hưởng tới task user không?

Gần như không: mỗi task user được fxrstor từ vùng lưu có FCW = 0x37f ngay lần đầu chạy, đè lên trạng thái x87 cũ. fninit chỉ đặt x87 về trạng thái chuẩn cho chính lúc đó.
